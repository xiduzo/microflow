title: Tokens
description: Link Penpot design tokens to a Microflow Studio flow, and read and change them in both directions.
---

The plugin links the design tokens in one token set, **MHB**, to Microflow Studio. Studio calls them variables, like Figma does. In Studio, a [Design variable](/docs/microflow-studio/nodes/express/figma) node can read and change each token. Values go both ways:

- **Hardware → Penpot.** A value arrives at one of the node's inputs. The plugin writes it into the token, and Penpot updates every shape that uses the token.
- **Penpot → hardware.** You change the token in Penpot. The node sends the new value out of its `change` output.

<Callout title="Same broker, same Bridge ID">
Studio and the plugin find each other only when they use the same MQTT broker and the same Bridge ID. See [MQTT settings](/docs/microflow-penpot-plugin/mqtt).
</Callout>

---

## Set up the tokens

When you run the plugin, it uses the token set called **MHB** (short for Microflow Hardware Bridge). It creates the set, active, if the file has none. **Only tokens in the MHB set are linked.**

1. Run the **Microflow hardware bridge** plugin in your Penpot file.
2. Open the tokens panel and find the **MHB** set. Keep it active: Penpot does not resolve the tokens of an inactive set.
3. Create tokens in the set, and apply them to shapes so you can see them change.
4. In the plugin, click the list icon on the home screen. The **Variables** page lists every linked token.

## Supported token types

| Penpot token type | Studio type |
| --- | --- |
| `color` | `COLOR` |
| `number`, `dimension`, `opacity`, `rotation`, `sizing`, `spacing`, `borderWidth`, `borderRadius`, `fontSizes`, `letterSpacing` | `FLOAT` |
| `fontWeights`, `fontFamilies`, `textCase`, `textDecoration` | `STRING` |
| `shadow`, `typography` | not linked |

Penpot has no boolean tokens. Use a `number` token with `0` and `1` instead.

## How the plugin reads and writes a token

- It reads the token's resolved value. A token that refers to another token sends the value it resolves to.
- A color token with its own value keeps its alpha. The plugin writes colors back as `#rrggbb`, or `#rrggbbaa` when the color is not fully opaque.
- The plugin writes numbers without a unit. A `dimension` token with the value `12px` becomes `12` after Studio changes it.
- When Studio writes a value into a token that refers to another token, the plain value replaces the reference.

Studio links to a token by its ID, not by its name. You can rename a token, and it stays linked. If you delete a token and create a new one with the same name, pick the new one again in Studio.

## Link a token to a node

1. Run the plugin in your Penpot file. Check that its **MQTT** dot is green.
2. In Studio, add a **Design variable** node to your flow.
3. In the node settings, select the **Broker** that the plugin uses.
4. Check that the plugin uses the node's Bridge ID. See [MQTT settings](/docs/microflow-penpot-plugin/mqtt#the-bridge-id).
5. Open the node's **variable** list and pick your token. When a Figma and a Penpot plugin are both connected, the names end in "(Figma)" or "(Penpot)".

The node's inputs change to match the type of the token.

## Hardware → Penpot

Connect a value to one of the node's inputs. The plugin writes the new value into the token.

| Studio type | Inputs | What they do |
| --- | --- | --- |
| `FLOAT` | `set`, `increment`, `decrement`, `reset` | `set` uses the incoming number. `increment` and `decrement` add or subtract the incoming number (`true` counts as 1). `reset` sets 0. |
| `STRING` | `set` | Set the token to the incoming text. |
| `COLOR` | `red`, `green`, `blue`, `opacity` | Change one channel. Red, green and blue take 0–255. Opacity takes 0–100. |

**Example:** Potentiometer → Map (0–1023 to 0–100) → the `set` input of a `sizing` token. Studio ships this flow as the **Sensor to Figma or Penpot** template.

A value that does not fit the token is dropped. The plugin shows a message when it ignores a value.

## Penpot → hardware

Change the token in Penpot. The plugin checks for changes four times a second, and again each time Penpot saves the file. It sends the new value, and the node sends it out of its `change` output. Changes made by other people in the same file reach Studio the same way, as long as your plugin is running.

**Example:** a `number` token from 0 to 100 → Map (0–100 to 0–255) → LED on pin 9. Studio ships this flow as the **Figma or Penpot to LED** template.

The `change` output fires for every new value: a change made in Penpot, and a change made through the node's own inputs.

## Advanced: MQTT topics

Other MQTT clients can use the same tokens, for example a script, a Raspberry Pi or your own firmware. The plugin's **Variables** page has two copy buttons for each token: the topic that carries its value, and the topic that changes it.

The Penpot plugin uses the same protocol as the Figma plugin, with `penpot` as its tool name:

| Topic | Sender | Payload | Retained |
| --- | --- | --- | --- |
| `microflow/{bridgeId}/penpot/status` | plugin (last will) | `connected` / `disconnected` | yes |
| `microflow/{bridgeId}/penpot/variables` | plugin | `{[id]: {id, name, resolvedType}}` | yes |
| `microflow/{bridgeId}/penpot/variable/{wireId}` | plugin | JSON value | no |
| `microflow/{bridgeId}/app/variable/{wireId}/set` | Studio | JSON value | no |

For a Penpot token, `{wireId}` is the token's ID, a uuid, as it is. For the full topic table, the request/answer topics and the payload rules, see [MQTT topics](/docs/microflow-hardware-bridge/variables/manipulating#advanced-mqtt-topics) in the Figma docs. They apply to both plugins.

## Limitations

- **Workspace only.** Penpot does not run plugins in view mode. The bridge links hardware to the tokens of a file that is open in the workspace.
- **Keep the plugin open.** When you close the plugin, the link stops. Studio then shows "Penpot plugin is not connected" on the node.
- **No boolean tokens.** Use a `number` token with `0` and `1`.
- **Keep the MHB set active.** The tokens of an inactive set do not resolve, so the plugin cannot read them.
- **Shared brokers.** On a public broker, the Bridge ID is the only thing that keeps your values apart from other people's. Use your [own broker](/docs/how-to/run-your-own-mqtt-broker) for anything private.
