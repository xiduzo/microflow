The Microflow plugin for [Penpot](https://penpot.app/) links the design tokens in a Penpot file to a flow in [Microflow Studio](/docs/microflow-studio). It is the Penpot counterpart of the [Hardware Bridge for Figma](/docs/microflow-hardware-bridge), and it speaks the same protocol. A sensor can change a token in your design, and a change to a token can drive your hardware.

**Example:** you turn a potentiometer on your desk, and a shape in your Penpot file grows and shrinks with it.

<Callout type="warn" title="The bridge works in the workspace, not in view mode">
Penpot runs plugins only in the workspace. The bridge links your hardware to the tokens of a file that is open in the workspace, with the plugin running. It does not reach view mode or a running prototype.
</Callout>

---

## Status

The plugin works end to end: Studio can read and change tokens, and token changes reach Studio. It is not in Penpot's plugin directory yet, and there is no hosted version. You install it from a local development server, or you host a build yourself.

## How it works

1. You run the plugin in a Penpot file. The plugin uses the tokens in a token set called **MHB** (Microflow Hardware Bridge). It creates the set if the file has none.
2. In Studio, a [Design variable](/docs/microflow-studio/nodes/express/figma) node lists those tokens. You pick one and connect the node to the rest of your flow.
3. Studio and the plugin send messages to each other through an [MQTT broker](/docs/microflow-penpot-plugin/mqtt). Both must use the same broker and the same **Bridge ID**.

When your flow sends a value into the node, the plugin writes it into the token. When you change the token in Penpot, the node sends the new value out of its `change` output.

## Install

You need [Bun](https://bun.sh) and a copy of the [Microflow repository](https://github.com/xiduzo/microflow). Run `bun install` in the repository root first. See [Build from source](/docs/contributing/build-from-source).

**From the development server:**

1. Start the server:

   ```sh
   cd apps/penpot-plugin
   bun run dev
   ```

2. In Penpot, open the plugin manager and install `http://localhost:5173/manifest.json`.

Keep the server running while you use the plugin.

**From your own server:**

1. Build the plugin:

   ```sh
   cd apps/penpot-plugin
   bun run build
   ```

2. Serve the `dist/` folder from any web server that sends CORS headers. It can live under any path.
3. In Penpot, open the plugin manager and install the URL of `manifest.json` in that folder.

The plugin appears in Penpot as **Microflow hardware bridge**. It asks for permission to read and change the file's content and to read its library.

## Set it up

1. In Studio, open **Configuration → MQTT** and add a broker. For a quick start, use the plugin's default broker: `wss://test.mosquitto.org:8081/mqtt`.
2. In your flow, add a **Design variable** node and select that broker. The node shows its Bridge ID. Click **copy bridge ID** in the node settings.
3. In the plugin, click the gear icon to open the MQTT settings. Paste the Bridge ID, keep the default broker URL, and click **Save MQTT settings**.
4. Add a token to the **MHB** token set. See [Tokens](/docs/microflow-penpot-plugin/variables).
5. In Studio, pick the token in the node's **variable** setting and connect the node.

The plugin's home screen shows two status dots:

- **MQTT** is green when the plugin is connected to the broker.
- **Microflow studio** is green when a Studio flow with a Design variable node uses the same broker and Bridge ID.

## Limitations

- The bridge works only while the file is open in the workspace and the plugin is running.
- Penpot has no boolean tokens. Use a number token with `0` and `1`.
- The MHB token set must be active. Penpot does not resolve the tokens of an inactive set.
- On a public broker, the Bridge ID is the only thing that keeps your values apart from other people's. See [MQTT settings](/docs/microflow-penpot-plugin/mqtt).

## Why Penpot?

Penpot is open source and you can host it yourself. That makes it a good fit if you:

- want to keep designs out of third-party clouds,
- work on internal or sensitive products,
- prefer free, open-source tools.

With a self-hosted Penpot and your [own MQTT broker](/docs/how-to/run-your-own-mqtt-broker), your designs and the values the bridge sends stay on your own network.
