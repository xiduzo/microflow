In the last lesson, time told the LED what to do. In this one, *you* will — by pressing a button.

## What you need

- Everything from the [first flow](/docs/learn/first-flow)
- A push-button (a momentary switch)
- A 10kΩ resistor (a "pull-down" resistor)
- A breadboard and a few jumper wires
- An LED and a 220Ω resistor (or skip these and reuse the built-in LED on pin 13)

## Step 1 — Wire the button

A button on its own is not enough — you also need a **pull-down resistor**, which makes sure the input reads `LOW` when the button is not pressed (otherwise it floats randomly).

| Connection | From | To |
| --- | --- | --- |
| Power | Arduino 5V | One side of the button |
| Signal | Other side of the button | Arduino digital pin 2 *and* one end of the 10kΩ resistor |
| Ground | Other end of the 10kΩ resistor | Arduino GND |

Pressing the button connects 5V to pin 2 directly; releasing it leaves pin 2 connected to GND through the resistor.

<Callout type="info" title="No breadboard? Use the built-in pull-up">
If you wire the button between pin 2 and GND with no resistor, turn on the Button node's **Pull-up** setting instead. The board uses its own internal resistor, and the reading inverts — pressed becomes `LOW`. Turn on **Invert** as well if you would rather not think about that.
</Callout>

## Step 2 — Wire the LED (skip if reusing pin 13)

| Connection | From | To |
| --- | --- | --- |
| Signal | Arduino pin 9 | One leg of the 220Ω resistor |
| LED | Other leg of the resistor | Long leg (anode) of the LED |
| Ground | Short leg (cathode) of the LED | Arduino GND |

## Step 3 — Build the flow

In Microflow Studio, create a new flow and add:

1. A [**Button**](/docs/microflow-studio/nodes/sense/button) node — set **Pin** to `2`.
2. An [**LED**](/docs/microflow-studio/nodes/express/led) node — set **Pin** to `9` (or `13` if you skipped step 2).
3. Draw **two** edges:
   - Button `true` → LED `true`
   - Button `false` → LED `false`

Two edges, not one. The first turns the light on; the second turns it off. Wire only the first and the LED comes on and stays on — which looks exactly like broken hardware and is the most common mistake in this build.

## Step 4 — Try it

Press the button. The LED should turn on. Release the button. The LED should turn off.

If nothing happens:

- **Is the second edge there?** If the LED comes on and never goes off, `false → false` is missing.
- **Is the sensor side alive?** Drop a [**Monitor**](/docs/microflow-studio/nodes/express/monitor) node on the canvas and connect the Button's `value` output to it. Press the button — the Monitor should show `1`. If it stays at `0`, the button is wired wrong or on a different pin.
- **Is the board still connected?** The sidebar should show a port name.
- **Does the pin in the node match the pin on the board?** See [Nothing happens on the board](/docs/troubleshooting/pin-conflicts).

## What just happened?

The Button node watches pin 2 and reports what it sees on several outputs at once: `true` while it is held, `false` while it is up, `event` on any change, `hold` on a long press, and `value` as `1` or `0`. You used two of them. The LED's `true` and `false` inputs are commands — arrive at one and the light does that thing. No "if-then" logic was needed.

This is the **sense → express** pattern: input from the world, output to the world.
