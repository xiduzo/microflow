By the end of this lesson the small LED already soldered to your board will blink once a second, and you will have built the flow that does it. No extra components.

## What you need

- A computer running Windows, macOS, or Linux — or Chrome, Edge, or Opera.
- An **Arduino Uno**, **Arduino Nano**, or **ESP32**.
- A USB cable that carries data.
- Microflow Studio, [connected to your board](/docs/how-to/connect-a-microcontroller).

<Callout type="info" title="There is a shortcut, but do not take it yet">
Studio ships this flow as the **Blink** template under **Templates** in the sidebar. Building it by hand once is worth the five minutes.
</Callout>

## Step 1 — Confirm your board is connected

Look at the microcontroller status in the sidebar. It should show a serial port name — something like `COM3` or `/dev/cu.usbmodem14201`.

If it says **No microcontroller connected**, or **Connect board** in the browser, stop here and follow [Connect a microcontroller](/docs/how-to/connect-a-microcontroller). Nothing below will work until this is right.

## Step 2 — Add an Interval node

You need something that fires repeatedly. The [Interval](/docs/microflow-studio/nodes/generate/interval) node does exactly that.

1. Press `Cmd/Ctrl + K` to open the **Add node** palette.
2. Type `interval`. It filters to the **Generate** group.
3. Press Enter. The node lands on the canvas.
4. Click the node and set **Interval** to `1000` — one tick per second.

## Step 3 — Add an LED node

Now something that acts on the tick.

1. Press `Cmd/Ctrl + K` again and type `led`.
2. You will see three results — **LED**, **LED Matrix**, **LED Strip**. Choose plain **LED**, under **Express**.
3. Place it to the right of the Interval node.
4. Click it and set **Pin** to `13` — the LED already on the board. No wiring today.

## Step 4 — Connect them

The dots on the right of a node are its **outputs**. The dots on the left are its **inputs**.

Drag from the Interval node's `event` output to the LED node's `toggle` input. A line appears between them — that is an **edge**, and it carries the tick from one node to the other.

<Callout type="info" title="Handles are small">
Zoom in first (`Cmd/Ctrl + =`) if the handles are hard to hit. Hovering over a node makes them easier to see.
</Callout>

## Step 5 — Watch it blink

The built-in LED should now toggle once a second. There was no run button to press — the flow started the moment the edge connected.

## If it is not blinking

Work down this list. It is in order of likelihood.

| Check | What to look for |
| --- | --- |
| The status in the sidebar | It must show a port name. **Connecting** or **Flashing firmware** means wait; anything else means [start here](/docs/troubleshooting/board-not-detected). |
| The LED node's **Pin** | It must be `13`. This is the most common mistake, and nothing on screen will tell you it is wrong. |
| The edge | It should run from `event` to `toggle`. Click it — a selected edge highlights. If nothing highlights, the connection never completed. |
| The Interval's value | The node shows its live value. If it is not changing, the Interval is not running. |

Still nothing? Add a [Monitor](/docs/microflow-studio/nodes/express/monitor) node and connect the Interval's `event` output to it. If the Monitor ticks, the problem is between the LED node and the board. If it does not, the problem is the Interval.

## What just happened

- **Interval** emits a tick every 1000 ms.
- The tick travels along the edge.
- **LED** flips its pin between on and off each time one arrives.

Something generates a value, the value travels along an edge, something expresses it in the physical world. Every flow you build is that shape, repeated.
