At the end of this lesson, the small LED soldered to your board blinks once a second, and you have built the flow that drives it.

## What you need

- A computer running Windows, macOS, or Linux, or Chrome, Edge, or Opera.
- An **Arduino Uno**, an **Arduino Nano**, or an **ESP32**.
- A USB cable that carries data.
- Microflow Studio, [connected to your board](/docs/how-to/connect-a-microcontroller).

<Callout type="info" title="Build it by hand this once">
Studio ships this flow as the **Blink** template under **Templates**. Build it yourself the first time.
</Callout>

## Step 1 — Check the board is connected

Read the microcontroller status in the sidebar. It shows a serial port name, such as `COM3` or `/dev/cu.usbmodem14201`.

If it shows **No microcontroller connected**, or **Connect board** in a browser, stop here. Follow [Connect a microcontroller](/docs/how-to/connect-a-microcontroller) first. Nothing below works until the board is connected.

## Step 2 — Add an Interval node

A flow starts with a node that produces something. The [Interval](/docs/microflow-studio/nodes/generate/interval) node produces a tick on a schedule.

1. Press `Cmd/Ctrl + K` to open the **Add node** palette.
2. Type `interval`. The Interval node moves to the top, under **Generate**.
3. Press Enter to place the node on the canvas.
4. Click the node and set **Interval** to `1000`. That is one tick per second.

## Step 3 — Add an LED node

Now add a node that acts on the tick.

1. Press `Cmd/Ctrl + K` and type `led`. Three nodes match: **LED**, **LED Matrix**, and **LED Strip**.
2. Select **LED**, under **Express**, and place it to the right of the Interval node.
3. Click the LED node and set **Pin** to `13`. Pin 13 drives the LED already on the board, so you wire nothing.

## Step 4 — Connect the two nodes

The handles on the right of a node are its outputs. The handles on the left are its inputs.

Drag from the Interval node's `event` output to the LED node's `toggle` input. The line between them is an **edge**, and it carries each tick to the LED.

<Callout type="info" title="Handles are small">
Press `Cmd/Ctrl + =` to zoom in first. Hovering over a node also makes its handles easier to see.
</Callout>

## Step 5 — Watch the LED

The built-in LED now switches on and off once a second. There is no run button. The flow started when you connected the edge.

## If the LED does not blink

Check these in order.

| Check | What you want |
| --- | --- |
| The sidebar status | A port name. **Connecting** and **Flashing firmware** mean wait. Anything else: see [Board not detected](/docs/troubleshooting/board-not-detected). |
| The LED node's **Pin** | `13`. A wrong pin number is the most common cause, and nothing on screen reports it. |
| The edge | It runs from `event` to `toggle`. Click it. A selected edge highlights. If nothing highlights, the connection never completed. |
| The Interval node's value | It changes. A static value means the Interval is not running. |

If all four are correct, add a [Monitor](/docs/microflow-studio/nodes/express/monitor) node and connect the Interval node's `event` output to it. If the Monitor ticks, the fault is between the LED node and the board. If it does not, the fault is the Interval node.

## What just happened

- The Interval node emits a tick every 1000 ms.
- The tick travels along the edge.
- The LED node switches its pin each time a tick arrives.

One node generates a value. The value travels along an edge. Another node expresses the value in the physical world. Every flow you build repeats that shape.
