title: Link a sensor to Figma
description: Send a live hardware reading into a Figma variable with the Hardware Bridge.

The **Hardware Bridge** is a Figma plugin. It lets a Figma file react to a physical input. In this lesson a potentiometer drives a Figma variable, and the design responds while you turn the knob.

## What you need

- The flow from [Fade an LED with a potentiometer](/docs/learn/fade-with-potentiometer).
- A Figma account.
- The [Microflow Hardware Bridge](https://www.figma.com/community/plugin/1373258770799080545) plugin, installed in Figma.
- The Microflow Studio **desktop app**. Broker configuration is not available in a browser.

<Callout type="info" title="Template available">
Studio ships the flow half of this lesson as the **Sensor to Figma** template, under **Templates**.
</Callout>

## Step 1 — Open the plugin

In Figma, run **Plugins → Microflow Hardware Bridge**. On its first run the plugin creates a variable collection called **MHB**.

<Callout type="info" title="The Bridge reads the MHB collection only">
Variables in any other collection are ignored. This keeps your design system variables out of the live data path.
</Callout>

Leave the plugin panel open. Closing it stops the bridge.

## Step 2 — Match the broker and the identifier

Open the plugin's settings and note two fields:

- **Broker URL** — the MQTT broker both ends use.
- **Identifier** — the name that separates your project from everyone else's on that broker.

In Studio, open **Configuration → MQTT** and add the same broker. Then set the same identifier on the Figma node in step 4.

<Callout type="warn" title="The identifier is case sensitive">
`workshop-01` and `Workshop-01` are different projects. A mismatch produces no error. Both ends report a healthy connection and no values arrive.
</Callout>

## Step 3 — Create a variable

1. Open Figma's **Local variables** panel.
2. Select the **MHB** collection.
3. Create a variable named `pot_value`, of type **Number**, with a default of `0`.
4. Bind it to something visible, such as the width of a rectangle.

## Step 4 — Send from Studio

1. Add a [Figma](/docs/microflow-studio/nodes/express/figma) node to your potentiometer flow.
2. In its settings, select the broker and enter the identifier from step 2.
3. Select `pot_value` from the **Variable** list. The list comes from the plugin, so a populated list confirms both ends are talking.
4. Connect the Potentiometer node's `value` output to the Figma node's `set` input.

## Step 5 — Test it

Turn the knob. The `pot_value` variable updates, and every layer bound to it changes.

If nothing happens, check these in order.

| Check | What you want |
| --- | --- |
| The plugin panel | Open. A closed panel stops the bridge. |
| The identifiers | Identical at both ends, character for character. |
| The **Variable** list in the Figma node | Populated. An empty list means the plugin is unreachable. |
| The values in Studio | Connect a [Monitor](/docs/microflow-studio/nodes/express/monitor) to the Potentiometer node's output. |

See [MQTT will not connect](/docs/troubleshooting/mqtt-cant-connect) for the full checklist.

## What just happened

Studio publishes the reading to an MQTT broker. The plugin subscribes to it and writes the value into the Figma variable. Figma redraws when a variable changes.

<img src="/diagrams/studio-mqtt-bridge-figma.svg" alt="The signal flow: an Arduino potentiometer, into Studio's Figma node, out to an MQTT broker, into the Hardware Bridge plugin, into a Figma variable in the MHB collection." />

Studio and Figma never talk directly. A Figma plugin cannot reach a USB port, so both ends pass messages through the broker. That is why the broker and the identifier must match at both ends.
