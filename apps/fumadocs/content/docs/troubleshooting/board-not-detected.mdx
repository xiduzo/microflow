The board is plugged in and Studio does not connect to it. Work down this page in order. The checks are ordered by how often each cause is to blame.

## First, read the status

| Status | Meaning |
| --- | --- |
| **No microcontroller connected** | Desktop app: no serial port found. Start at check 1. |
| **Connect board** | Browser: you have granted no permission yet. See check 5. |
| **Use Chrome/Edge or the desktop app** | You are in Firefox or Safari. See check 5. |
| **Connecting** | Studio found a port. Wait a few seconds. |
| **Flashing firmware** | Studio is installing the firmware. Wait up to a minute. Do not unplug the board. |
| **Error** | The connection failed. Work through this page. |

## 1. The cable

Most broken boards are broken cables. Many USB cables carry power and no data, and look identical to cables that carry both. The board's power light comes on with either kind, so the light tells you nothing.

1. Try a different cable. Use one you have already uploaded a sketch with, if you have one.
2. Plug into the computer, not into a hub.

Assume a cable that came with headphones, a battery pack, or a phone charger carries power only.

## 2. Another program holds the port

A serial port has one occupant at a time.

Close anything else that talks to the board: the Arduino IDE's **Serial Monitor** or plotter, PlatformIO, a `screen` or `minicom` session, a second copy of Studio, and a second **browser tab** with Studio open.

On Windows, close the whole Arduino IDE rather than the Serial Monitor alone. Then unplug the board and plug it in again.

## 3. The driver

Official Arduino boards need no driver. Clones use a different USB-to-serial chip, usually CH340 or CP2102, which needs a driver on Windows and on older macOS.

Check whether your operating system sees the board at all:

- **Windows** — Device Manager → Ports (COM & LPT).
- **macOS** — System Information → USB.
- **Linux** — run `ls /dev/tty*` before and after you plug the board in.

If the operating system does not list the board, no application can reach it. Install the driver — see [Install board drivers](/docs/how-to/install-board-drivers).

**Windows, CH340 clone, "device not functioning":** the board appears as *USB-SERIAL CH340 (COM3)*, Studio still fails, and the same board works on macOS. CH340 driver 4.0 rejects the clone chip. Downgrade to 3.4 — see [CH340 clones and the "device not functioning" error](/docs/how-to/install-board-drivers#ch340-clones-and-the-device-not-functioning-error-windows).

## 4. The board

1. Plug in a different board. If that board connects, the first board is at fault.
2. Open the Arduino IDE and upload **File → Examples → 01.Basics → BareMinimum**.

If that upload fails, and especially if it reports `avrdude: stk500_recv()`, the board has a bootloader fault. Bootloader recovery needs an ISP programmer and is outside what Studio can do.

## 5. In a browser

Web Serial has rules the desktop app does not.

- **Firefox and Safari cannot reach a serial port.** Switch to Chrome, Edge, or Opera, or install the desktop app.
- **You must grant permission.** A status of **Connect board** means no board is granted. Click it and select your board. If you dismiss the chooser, nothing changes and no error appears.
- **Permission covers one origin and one device.** Permission granted on a local dev server does not apply to the hosted app.
- **One tab holds the port.** A second Studio tab cannot take a port the first tab holds. Close the other tab.
- **Policy can disable Web Serial.** An enterprise policy or a `chrome://flags` setting makes Studio report the browser as unsupported.

Studio reconnects to a granted board on its own, including after you unplug it.

## 6. Firmware

Studio checks the firmware on every connection: it probes the board, flashes the firmware if the probe fails, then connects. A board you have used with the Arduino IDE or another tool therefore recovers on the next connection.

Corrupt firmware is rarely the cause. When the flash itself fails, check 1 and check 2 are the usual reasons. To run the step yourself, see [Flash firmware manually](/docs/how-to/flash-firmware-manually).

## 7. Unsupported board

Microflow generates code for the **Arduino Uno**, the **Arduino Nano**, and the **ESP32**. Another board may connect and may partly work, but the generated sketch and the wiring diagram will be wrong for it, and no warning appears.

Check which target the flow uses — see [Choose a board target](/docs/how-to/choose-a-board-target).

## Still stuck

Open an issue on [GitHub](https://github.com/xiduzo/microflow-t-stack/issues) with:

- The board name, and whether it is genuine or a clone.
- Your operating system and version.
- The Studio version, and whether you use the desktop app or a browser.
- The exact status text in the sidebar.
- Whether the Arduino IDE reaches the same board.
- Whether your operating system lists the board as a serial device.

The last two answers separate a Microflow fault from a machine that cannot see the hardware.
