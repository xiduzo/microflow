---
title: The AI node does not answer
description: The LLM node is triggered and returns nothing, or returns something unusable.
---

The [LLM node](/docs/microflow-studio/nodes/express/llm) is far slower than anything else in Microflow. A node that is still working and a node that has failed look the same, unless you wire the node to tell you apart.

First the thinking light holds and an answer arrives. Second the thinking light holds and the error light fires instead.
</Clip>

## First, wire up `thinking` and `error`

Connect both status outputs to a [Monitor](/docs/microflow-studio/nodes/express/monitor) node in `raw` mode.

- **`thinking`** goes true when you trigger the node and false when the answer arrives.
- **`error`** fires when the model is unreachable or refuses the request.

These two outputs tell you which half of the problem you have.

## `thinking` never goes true

The trigger never arrived.

- Check that something is connected to the node's **`trigger`** input. The node does nothing on its own.
- Check that the upstream node fires. Connect a Monitor to its output.

## `thinking` goes true and stays true

The request left Studio and nothing came back.

- **Check the provider.** Open **Configuration → LLM** and run the test. It reports either that the provider is reachable, or the error. A failure here is not a fault in your flow.
- **Check the model name.** It must match the provider's name for the model exactly. Run `ollama list` to see the names.
- **Wait longer.** A large model on a modest machine takes tens of seconds. Try a smaller model.

## `error` fires

The provider answered with a failure.

- A wrong model name is the usual cause. Most providers report an unknown model as an error.
- A provider that needs an API key fails at authentication when no key is set.
- A machine that is asleep or on another network produces a connection error.

## The answer arrives and is unusable

- **The answer is too long.** Set the length in the **System** prompt: "Answer in one short sentence."
- **The answer ignores your values.** Reference each value as `{{name}}` in the prompt. Each placeholder adds an input handle. An unconnected handle substitutes nothing.
- **The answer differs every time.** Language models work this way. To get a fixed set of outcomes, decide with a [Compare](/docs/microflow-studio/nodes/decide/compare) node and use the model only for the wording.

## The configuration page is missing

AI provider configuration runs in the desktop app only. In a browser the page says so and saves nothing.

## Device lists are snapshots [#device-lists-are-snapshots]

Studio reads the provider list, the broker list, and the [MIDI](/docs/microflow-studio/nodes/sense/midi) node's **Device** list when you open the settings. A device you plug in afterwards appears only after you close and reopen the settings.

If a MIDI controller is still missing after that, check that your operating system sees it: Audio MIDI Setup on macOS, Device Manager on Windows. A MIDI controller plugs into the computer, not into the Arduino.
