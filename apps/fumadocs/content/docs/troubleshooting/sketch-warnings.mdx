---
title: Warnings in the generated sketch
description: What the triangle and the cross in the code view mean, and how to clear each one.
---

When you open **Show code**, Microflow checks the flow against the board target before it generates the sketch. There are two results:

- **A warning triangle.** The sketch generated. Part of the flow will not behave as the canvas suggests. The download works. Read the comments at the top of the sketch.
- **A cross.** Generation failed. **Download sketch** stays disabled until you fix the flow.

Every message names the node it refers to. Fix the node, not the sketch. Microflow regenerates the sketch each time you open the view.

## Pin does not exist on this target [#pins]

> Node … uses pin *N*, which is not a usable GPIO on board target '…' (absent or reserved — e.g. ESP32 GPIO 6-11 drive the onboard flash)

The pin is not on this board, or the board reserves it.

**Fix:** move the node to a pin the target has, or change the target. On an ESP32, never use GPIO 6 to 11. They drive the chip's flash memory, and the board does not boot without them.

## Not a PWM pin [#pwm]

> Node … (Servo) needs PWM on pin *N*, but pin *N* on board target '…' does not support PWM

> Node … drives brightness on pin *N*, which is not PWM-capable on board target '…' — the output degrades to on/off

LED brightness, vibration intensity, and servo angle all need a pin that holds a partial output. On an Uno or a Nano, those are pins 3, 5, 6, 9, 10, and 11, marked `~` on the board.

**Fix:** move the component to a PWM pin, on the board and in the node's settings.

The LED case is easy to miss. The LED still switches on and off, with nothing in between. If an LED refuses to dim and the canvas shows no error, this warning is the reason.

## Out of analog inputs [#analog]

> Node … needs an analog input, but board target '…' offers only *N* and the Flow already uses them all

> Node … reads analog input A*N*, but board target '…' has only *N* analog input(s)

An Uno and a Nano have six analog inputs, A0 to A5. A flow with seven analog sensors cannot run on either board.

**Fix:** use fewer analog sensors, move some to digital pins where the component allows it, choose a board with more inputs, or read an analog multiplexer through an [I2C Device](/docs/microflow-studio/nodes/sense/i2c-device) node.

## Needs networking [#networking]

> Node … requires networking, which board target '…' does not offer — the generated network code assumes an ESP32-class board

The flow uses a node that reaches the network, and the target has no network hardware. An Uno cannot reach a broker on its own.

**Fix:** change the target to ESP32, or keep the networking on the computer. Studio reaches MQTT brokers over the computer's connection, which works with any board.

## MIDI claims the hardware serial [#midi]

> Node … (Midi) uses serial MIDI on the board's primary hardware serial (31250 baud) — the USB Serial Monitor is unavailable while running, and a DIN-5 MIDI jack or shield is required

Serial MIDI takes the same lines the USB serial connection uses. The Arduino IDE's Serial Monitor stops working while the sketch runs, and the board needs a physical MIDI jack or shield.

**Fix:** if your controller plugs into the computer instead, this warning does not apply to your setup. Check the [MIDI node](/docs/microflow-studio/nodes/sense/midi) settings match your hardware.

## Node ids collide [#ids]

> Node … shares the generated identifier '…' with … — rename the node ids so they differ by more than punctuation

Two nodes generate the same variable name in C++, because their ids differ only by punctuation.

**Fix:** rename one node so the names differ by more than a dash or an underscore.
