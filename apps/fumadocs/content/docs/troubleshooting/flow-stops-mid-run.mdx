title: Flow stops mid-run
description: The flow worked, then the values stopped.
---

The flow ran, then stopped responding. Monitors freeze, the hardware sits still, and the sidebar still shows a connected port.

The Monitors freeze and the sidebar stops showing a port. On replug the status walks back to connected and the flow resumes.
</Clip>

## 1. Check that something should have changed

A flow with no [Generate](/docs/microflow-studio/nodes/generate) node — no Interval, Oscillator, or Constant — produces values only when a Sense input changes. A quiet sensor then looks like a frozen flow.

Press a button, turn a knob, or breathe on a temperature sensor. If a Monitor reacts, the flow is working.

## 2. Check the board status

Read the microcontroller status in the sidebar.

- **A port name.** The connection is live, and the fault is in the flow. Go to step 3.
- **No microcontroller connected**, **Connecting**, or **Error.** The USB connection dropped. Unplug the board and plug it in again. Studio reconnects on its own and re-flashes the firmware if it needs to.

USB connections drop for four common reasons: a marginal cable, a USB hub, a machine that suspends USB devices, and a component that draws too much current.

If the flow drops out every time a motor or an LED strip starts, the cause is power, not software. Power the component from a separate supply and join the grounds.

## 3. Check the Function nodes

A [Function](/docs/microflow-studio/nodes/shape/function) node running slow code is the most common cause of a stalled chain. The runtime stops infinite loops at 10,000 iterations, but slow code still holds up the nodes after it.

1. Connect a [Monitor](/docs/microflow-studio/nodes/express/monitor) before and after each Function node.
2. Watch for an input that changes while the output does not.

That node's code is the cause. Look for deep recursion, loops over large arrays, and string operations on large data.

A Function node that throws an error emits its last successful value, so the node looks like it is working while it repeats stale data. Check the Studio console for the error.

## 4. Check for a moving Stepper

A stepper motor takes real time to reach its target. A new command that arrives during a movement is queued or dropped, depending on the driver. If a [Stepper](/docs/microflow-studio/nodes/express/stepper) node ignores commands, wait for the current movement to finish.

## 5. Restart the connection

Unplug the board, wait five seconds, and plug it in again. Studio probes the board, re-flashes the firmware if it is missing, reconnects, and rebuilds the runtime. This clears stale state.

In a browser this works the same way. Studio reconnects to a board you have already granted.

## 6. Restart Studio

1. Quit Microflow Studio.
2. Unplug the board, wait five seconds, and plug it in again.
3. Open Studio and the flow.

If you need this often, [report it](https://github.com/xiduzo/microflow-t-stack/issues) with the steps that lead to it.
