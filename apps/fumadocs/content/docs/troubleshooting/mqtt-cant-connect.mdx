---
title: MQTT can't connect
description: Studio or a Figma or Penpot plugin does not connect to the broker, or values do not arrive.
---

Work through these checks if Studio and a design-tool plugin do not find each other. Typical signs:

- The plugin's **MQTT** dot stays red or amber.
- The plugin's **Microflow studio** dot stays grey or red.
- The Design variable node shows "Figma plugin is not connected", "Penpot plugin is not connected" or "No Figma or Penpot plugin is connected".

## 1. Are both on the same broker?

The most common cause: Studio and the plugin use different brokers.

- In **Microflow Studio**, open *Configuration → MQTT* and note the URL of the broker that your Design variable node uses.
- In the **plugin**, click the gear icon and note the **Broker URL**.

The simplest setup uses the exact same URL in both. The plugins and Studio in the browser need a `ws://` or `wss://` URL.

## 2. Do the Bridge IDs match?

Studio and the plugin only find each other when they use the same Bridge ID.

- In Studio, the Design variable node settings show the **bridge ID**.
- In the plugin, the MQTT settings show the **Bridge ID**.

Copy the ID from Studio with **copy bridge ID**, paste it into the plugin, and click **Save MQTT settings**. See [The Bridge ID](/docs/microflow-hardware-bridge/mqtt#the-bridge-id).

## 3. Are the credentials the same?

If the broker requires authentication, Studio and the plugin need a valid username and password. A small typo is enough to fail. Most brokers do not report "wrong password" in a way you can see.

## 4. Is the broker reachable?

For the **default public broker** (`test.mosquitto.org`): it is sometimes slow or down. Test it from another tool:

```sh
mosquitto_sub -h test.mosquitto.org -t test
```

If that hangs or fails, the broker is the problem. Wait, or [run your own](/docs/how-to/run-your-own-mqtt-broker).

For a **self-hosted broker**:

- Is the broker process running? `ps aux | grep mosquitto` (Linux/macOS).
- Is the host reachable? `ping <broker-host>` from each machine.
- Is the port open? `nc -zv <broker-host> <port>`. A firewall on the broker's machine often blocks it.
- Does the broker have a WebSocket listener? The plugins cannot use plain MQTT on port `1883`.

## 5. Is your network blocking the connection?

Many company and school networks block ports other than 80 and 443. The public broker uses `8081` for secure WebSockets.

- Try the connection from your phone's hotspot. If it works there but not on your Wi-Fi, the network blocks it.
- Workarounds: use a broker with a WebSocket listener on port 443, or run a broker on your own computer.

## 6. Is one side stuck?

Restart in this order:

1. Close and reopen the plugin in Figma or Penpot.
2. Reload Studio in the browser, or quit and reopen the desktop app.

The plugin's **Microflow studio** dot can stay green after Studio has crashed, because the broker keeps Studio's last status. Restarting Studio fixes it.

## 7. Values do not arrive

Both dots are green, but a value does not change.

- The plugin must be open in the editor. Plugins do not run in a Figma prototype or in Penpot's view mode.
- In Figma, the variable must be in the **MHB** collection. The plugin reads the collection's default mode.
- In Penpot, the token must be in the **MHB** token set, and the set must be active.
- The Design variable node must have the variable selected, and show no error.
- The value must fit the variable's type. A value that does not fit is dropped: text cannot set a Number variable, for example.

To see the messages themselves, watch the bridge's topics. In Studio, open *Configuration → MQTT*, select the broker, and type this in the console, with your own Bridge ID:

```
subscribe microflow/your_bridge_id/#
```

Or run it from a terminal:

```sh
mosquitto_sub -h test.mosquitto.org -t 'microflow/your_bridge_id/#' -v
```

You should see the plugin's variable list on `…/figma/variables` or `…/penpot/variables`, and a message for each value change. If nothing shows up, the plugin is on another broker or Bridge ID.
