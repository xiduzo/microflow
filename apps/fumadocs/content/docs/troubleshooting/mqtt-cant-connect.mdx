title: MQTT will not connect

These are two different faults with the same appearance. Decide which one you have first.

- **The connection never comes up.** Start at [The connection fails](#the-connection-fails).
- **Both ends report a connection, and no values arrive.** Go to [Connected, but nothing arrives](#connected-but-nothing-arrives). No connection check helps here.

## The connection fails

### 1. The URL is not a WebSocket URL

This is the most common cause. Microflow speaks MQTT over WebSockets only.

- Accepted: `wss://host:port/path` and `ws://host:port/path`.
- Rejected: `mqtt://`, `mqtts://`, and `tcp://`.

Broker documentation usually gives the native address, `mqtt://host:1883`, because a native client needs it. Use the broker's WebSocket port instead. A broker whose documentation never mentions WebSockets does not work with Microflow.

Studio fills in what you leave out: protocol `wss`, port `8883`, path `/mqtt`. So `broker.example.com` becomes `wss://broker.example.com:8883/mqtt`, which is correct only if your broker listens there.

### 2. Credentials

If the broker requires a username and password, enter the same values at both ends. Most brokers report a wrong password as a failed connection and nothing more specific.

### 3. Prove the broker with the test client

Do not build a flow to test a broker. Open **Configuration → MQTT** in the desktop app and use the **Test Client**.

1. Subscribe to `test/#`.
2. Publish any message to `test/message`.
3. Watch for the message to arrive.

If the message arrives, the broker works and the fault is downstream. If it does not, fix the broker before you go further.

### 4. Your network blocks the port

Corporate and institutional networks often block outbound ports other than 80 and 443.

Try the same broker on a phone hotspot. If it works there and fails on the office network, the network is the cause. Use a broker that serves WebSockets on port 443, or run a broker locally.

### 5. The broker

For a self-hosted broker:

```sh
ps aux | grep mosquitto          # is it running?
nc -zv broker.example.com 8883   # is the port reachable?
```

A default Mosquitto install serves native MQTT only. Add a WebSocket listener — see [Run your own MQTT broker](/docs/how-to/run-your-own-mqtt-broker).

## Connected, but nothing arrives

Both ends report a connection. No error appears. No values arrive. One of these three is the cause.

### 1. The unique identifiers differ

Microflow addresses every message under your unique identifier:

```
microflow/<unique-id>/figma/variable/<variable-id>
```

If Studio uses `workshop-01` and the plugin uses `Workshop-01`, both ends connect, both stay healthy, and neither hears the other. The identifier is case sensitive, and no error reports a mismatch.

Compare the two identifiers character by character. Check this first, every time.

### 2. The plugin is closed

A Figma or Penpot plugin runs only while its panel is open. Closing the panel stops the bridge and reports nothing. Open the panel again.

### 3. The node uses a different variable

Microflow addresses a variable by its ID, not its name. Renaming a variable in Figma is safe. Deleting a variable and creating a new one with the same name is not.

Open the node's settings and select the variable again. If the variable list is empty, the plugin is unreachable — go back to check 1.

## Restart order

To clear stale state, restart in this order:

1. Close and reopen the plugin panel in Figma or Penpot.
2. Reopen the flow in Studio.
3. Quit and reopen Studio.
