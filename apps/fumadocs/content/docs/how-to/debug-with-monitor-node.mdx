The [Monitor](/docs/microflow-studio/nodes/express/monitor) node shows the value passing one point on the canvas, while the flow runs. It changes nothing, and it passes the value straight through, so you can add one anywhere.

<Video title="Debug a flow with Monitor" duration="3:30" script="/docs/videos/debug-with-monitor">
A flow that does nothing, bisected with two Monitor nodes until the broken node falls out.
</Video>

## The method

Find the first point where the value is wrong.

1. Connect a Monitor node to the input of the node you suspect.
2. Connect a second Monitor node to its output.
3. Run the flow and compare the two.

| What you see | What it means |
| --- | --- |
| The input is correct, the output is wrong | The suspect node is at fault. Check its settings. |
| The input is already wrong | The fault is upstream. Move both Monitors back one node and repeat. |

Two or three rounds isolate a fault in a flow of any size.

An output feeds as many inputs as you like, so adding a Monitor never disturbs an existing edge.

## The two modes

Set **Type** in the Monitor node's settings.

- **`graph`** plots the value over time. Use it for anything continuous, to see noise, lag, or a stuck value.
- **`raw`** prints the value. Use it for text, for booleans, and for any number you need to read exactly.

If a graph shows nothing where you expect a value, switch to `raw`. A constant `0` is hard to see on a graph and obvious as text.

## Common cases

**An LED does not respond.** Connect a Monitor between the upstream node and the LED node, then trigger the input. If the Monitor changes, the flow is correct and the fault is in the wiring or the LED node's settings. If it does not change, the fault is upstream.

**The values are wrong somewhere.** Connect a Monitor to every edge and run the flow once. The first Monitor showing a wrong value names the node.

**The values jump.** Set the Monitor to `graph`. A fuzzy line is noise — see [Smooth a noisy sensor](/docs/learn/smooth-a-sensor). A clean line that steps up and down many times for one physical event is bounce — see [Debounce a button](/docs/how-to/debounce-a-button).

## Keep them while you build

Leave the Monitor nodes in place while you work on a flow. They document what you were checking. Delete them before you share the flow if you want a clean canvas.
