---
title: Debounce a button
description: Stop a single button press from being read as several presses.
---

Mechanical buttons do not switch cleanly. When you press one, the contacts inside it bounce against each other for a few milliseconds before settling. The Arduino reads each bounce as a separate event — so one press becomes "press, release, press, release, press" all in a heartbeat.

One press counted three times on a Monitor graph, then the same press counted once with Forget previous on.
</Video>

This is called **bouncing**, and the fix is **debouncing**.

<Callout type="info" title="Template available">
  Studio ships a working example as the **Debounced Button** template — a button, a 30 ms debounced Delay, and a Counter you can watch increment exactly once per press.
</Callout>

## When you need it

- A button is supposed to advance a counter by 1, but jumps by 2 or 3.
- A toggle (e.g. with a [Counter](/docs/microflow-studio/nodes/generate/counter) node) flips back and forth too fast.
- A motion or vibration sensor fires bursts of events for a single physical event.

You will *not* need this for analog sensors (potentiometers, light sensors) — they have a different problem (noise) which the [Smooth](/docs/microflow-studio/nodes/shape/smooth) node handles.

## The fix: a Delay node with Forget previous

The [Delay](/docs/microflow-studio/nodes/decide/delay) node has a **Forget previous** setting. That is what turns it into a debounce: with it on, a new trigger **restarts** the wait instead of queueing behind it, so the node only fires once nothing new has arrived for the full duration.

1. Put a Delay node between the sense node and whatever it drives: Button `event` → Delay `trigger`, Delay `event` → the next node.
2. In the Delay node's settings:
   - **Delay** — `30` ms for a typical push-button, `200` for a vibration sensor.
   - **Forget previous** — on.

Press the button: the Delay sees five rapid changes as the contacts bounce, restarts its timer on each one, and passes exactly one event through 30 ms after the bouncing stops.

With **Forget previous** off, the same node does the opposite job — it holds each event and passes every one of them on, late. That is a delay, not a debounce, and on a bouncing button it makes things worse.

## Counting presses

The [Counter](/docs/microflow-studio/nodes/generate/counter) node has no settings and no debounce of its own — it counts every event it receives. Debounce before it, not inside it: Button `event` → Delay (**Forget previous** on) → Counter `increment`.

## Picking a duration

| Component | Typical debounce |
| --- | --- |
| Push-button | 20–50 ms |
| Toggle switch | 10–30 ms |
| Reed switch | 5–20 ms |
| Vibration sensor (taps) | 100–300 ms |
| PIR motion sensor | already handled internally — usually no debounce needed |

Start short and increase only if you still see double-fires. Long debounce times make a button feel sluggish.

## Verify it worked

Drop a [Monitor](/docs/microflow-studio/nodes/express/monitor) node in `raw` mode *before* and *after* the Delay. Press the button once. The "before" Monitor flickers several times; the "after" Monitor ticks once.

If both flicker, **Forget previous** is off.
