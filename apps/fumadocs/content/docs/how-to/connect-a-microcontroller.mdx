## Before you start

- A supported board: **Arduino Uno**, **Arduino Nano**, or **ESP32**.
- A USB cable **that carries data**. Many cables sold with phones and battery packs carry power only, and look identical.
- Microflow Studio: the [desktop app](https://github.com/xiduzo/microflow-t-stack/releases), or the web app in Chrome, Edge, or Opera.

## Connect on the desktop app

1. Plug the board into the computer. Use a port on the computer, not a hub.
2. Open Microflow Studio.
3. Find the microcontroller status in the sidebar, below the flow switcher.
4. Wait. Studio finds the board on its own. There is nothing to click.

The board is connected when the status shows a serial port name, such as `COM3` or `/dev/cu.usbmodem14201`.

## Connect in a browser

A web page cannot open a serial port without your permission, so the browser adds one step.

1. Plug the board into the computer.
2. Open Studio in Chrome, Edge, or Opera. Firefox and Safari cannot reach a serial port.
3. Click **Connect board** in the sidebar. The browser opens its own port chooser.
4. Select your board and confirm.

Studio reconnects to that board on its own from now on, including after you unplug it. The chooser opens only for a board you have not granted before.

## What the statuses mean

| Status | Meaning | What to do |
| --- | --- | --- |
| **No microcontroller connected** | Desktop app: no board found. | Check the cable and the port. |
| **Connect board** | Browser: you have granted no permission yet. | Click it and select your board. |
| **Connecting** | Studio found a port and is checking the board. | Wait a few seconds. |
| **Flashing firmware** | Studio is installing the firmware. | Wait up to a minute. Do not unplug the board. |
| A port name | Connected. Your flow runs on the board. | Build something. |
| **Error** | The connection failed. | See [Board not detected](/docs/troubleshooting/board-not-detected). |

<Callout type="warn" title="Do not unplug during Flashing firmware">
An interrupted flash can leave the board in a state Studio cannot recover from. A first flash takes up to a minute.
</Callout>

## Verify it worked

1. Add any [Sense](/docs/microflow-studio/nodes/sense) node.
2. Add a [Monitor](/docs/microflow-studio/nodes/express/monitor) node and connect the two.
3. Touch the component.

Values in the Monitor mean the cable, the board, the firmware, and the flow all work.

## About the firmware step

Your board knows nothing about Microflow when it arrives. Studio puts a small program on the board that takes orders over USB, such as *set pin 9 high* or *report changes on pin 2*.

Studio checks the firmware on every connection:

1. Studio probes the board for the firmware.
2. If the firmware is missing, Studio flashes it and probes again.
3. Studio connects.

A board you have used for something else therefore recovers on its own. To run the step yourself, see [Flash firmware manually](/docs/how-to/flash-firmware-manually).

## Supported boards

| Board | Notes |
| --- | --- |
| Arduino Uno | The default target. Digital pins 0–13, analog A0–A5. PWM on 3, 5, 6, 9, 10, 11. |
| Arduino Nano | The same chip and pin layout as the Uno, in a smaller package. |
| ESP32 | Different pin numbering. The only target with networking. |

Set the target for each flow in the board picker. See [Choose a board target](/docs/how-to/choose-a-board-target). A wrong target still connects, but produces a wrong wiring diagram and a wrong exported sketch.

## If the board does not connect

Work through [Board not detected](/docs/troubleshooting/board-not-detected). The causes there are ordered by how often each one is to blame.
