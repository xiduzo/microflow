---
title: Flash firmware manually
description: Upload StandardFirmata to a board yourself with the Arduino IDE, when automatic flashing is not an option.
---

Microflow Studio flashes StandardFirmata automatically when you connect a supported board that does not run it yet. This guide covers the cases where you need to do it yourself.

## When you need it

- Your board is not one that Studio flashes automatically (Uno, Nano, Mega, Leonardo, Micro).
- Automatic flashing keeps failing, and the board status ends in **Error**.
- The board already runs Firmata but behaves strangely. Studio does not re-flash a board that answers as Firmata, so you have to replace the firmware yourself.

<Callout title="Board runs another sketch?">
  You do not need this guide. Connect the board to Studio: it sees that Firmata is missing and flashes it for you.
</Callout>

## Steps

1. **Install the [Arduino IDE](https://www.arduino.cc/en/software).**
2. **Free the serial port.** Quit the Microflow desktop app, or click the green board status in the browser to disconnect. Only one program can use the port at a time.
3. **Open the firmware sketch.** Choose one:
   - **Microflow's StandardFirmata** — download the files in [`apps/web/src-tauri/src/flasher/hex/StandardFirmata`](https://github.com/xiduzo/microflow/tree/main/apps/web/src-tauri/src/flasher/hex/StandardFirmata) into one folder named `StandardFirmata`, and open `StandardFirmata.ino`. This version adds support for addressable LED strips (the [Pixel](/docs/microflow-studio/nodes) node).
   - **Stock StandardFirmata** — in the Arduino IDE, choose **File → Examples → Firmata → StandardFirmata**. It has no support for addressable LED strips.

   The [Stepper](/docs/microflow-studio/nodes/express/stepper#firmware-requirement) node needs ConfigurableFirmata instead of either sketch.
4. **Select your board and port** in the board selector at the top of the Arduino IDE.
5. **Click Upload** and wait until the IDE reports *Done uploading*. Do not unplug the board.
6. **Close the Arduino IDE**, then open Studio and [connect the board](/docs/how-to/connect-a-microcontroller).

## Verify it worked

The board status in the sidebar goes from **Connecting** straight to the port name, without **Flashing firmware**. Then drop a [Monitor](/docs/microflow-studio/nodes/internal/monitor) node onto the canvas, connect any Sense node to it, and watch values appear. If the Monitor stays blank, see [Pin conflicts](/docs/troubleshooting/pin-conflicts) or [Board not detected](/docs/troubleshooting/board-not-detected).

## If uploading keeps failing

The most common cause is **another program holding the serial port**. The Arduino IDE's Serial Monitor is the usual suspect. Close every program that talks to the board and try again.

If the failure persists across reboots, the board may have a bootloader issue. Upload the *Bare Minimum* example sketch first (**File → Examples → 01.Basics → BareMinimum**). If even that fails, the board needs hardware-level recovery, which is outside Microflow's scope.
