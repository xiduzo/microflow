---
title: Send a sensor reading to Figma
description: Push a live value from a hardware sensor into a Figma variable.
---

A sensor drives a Figma variable, and every layer bound to that variable updates live.

<Video title="Hardware in a Figma prototype" duration="6:00" script="/docs/videos/figma-bridge">
The whole bridge, both directions, including an identifier mismatch that reports a healthy connection.
</Video>

## What you need

- The Microflow Studio **desktop app**. The browser build cannot configure a broker.
- A working sense flow, such as a [Potentiometer](/docs/microflow-studio/nodes/sense/potentiometer) on `A0`.
- A Figma file with the [Microflow Hardware Bridge](https://www.figma.com/community/plugin/1373258770799080545) plugin running.
- The same broker and the same identifier at both ends.

## Steps

### 1. Create a variable

1. In Figma, open **Local variables**.
2. Select the **MHB** collection. The plugin creates it on its first run, and reads no other collection.
3. Create a variable whose type matches your sensor.

| Sensor | Figma variable type |
| --- | --- |
| Button, Switch, Motion | Boolean or Number |
| Potentiometer, LDR, Force, Analog Sensor | Number |
| A Function node returning text | String |

4. Name it, for example `light_level`.
5. Bind it to a layer property such as width, fill colour, or opacity, so you can see it change.

### 2. Add a Figma node in Studio

1. Add a [Figma](/docs/microflow-studio/nodes/express/figma) node to your flow.
2. In its settings, select the broker and enter the identifier from the plugin's settings.
3. Select your variable from the **Variable** list. Studio reads the list from the plugin, so a populated list confirms both ends are talking.
4. Connect your sense node's `value` output to the Figma node's `set` input.

The handles on the Figma node follow the variable's type. A boolean variable shows `true`, `false`, and `toggle`. A number shows `set`, `increment`, `decrement`, and `reset`. A colour shows `red`, `green`, `blue`, and `opacity`.

<Callout type="info" title="Template available">
Studio ships this pattern as the **Sensor to Figma** template, under **Templates**.
</Callout>

### 3. Set the update rate

The Figma node's **Debounce time** limits how often it sends, in milliseconds. The default of `100` keeps a noisy sensor from flooding the bridge. Lower it for finer updates. Raise it if Figma struggles.

For a jittery sensor, add a [Smooth](/docs/microflow-studio/nodes/shape/smooth) node before the Figma node instead.

## Verify it worked

Move the sensor. The variable's value changes in Figma's variable panel, and the bound layer changes with it.

If nothing happens, check these in order.

| Check | What you want |
| --- | --- |
| The plugin panel | Open. A closed panel stops the bridge. |
| The identifiers | Identical at both ends, character for character. |
| The **Variable** list | Populated. An empty list means the plugin is unreachable. |
| The sensor | Connect a [Monitor](/docs/microflow-studio/nodes/express/monitor) node to the sense node's output. |

See [MQTT will not connect](/docs/troubleshooting/mqtt-cant-connect).

## Send several variables

Add one Figma node per variable. Each node binds to its own variable, and each can read from a different part of the flow.
