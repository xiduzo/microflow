Several people can open the same flow and see each other's edits as they happen. This page explains how, and what follows from it for a hardware project.

## CRDTs, not save and merge

The collaboration layer uses [Yjs](https://yjs.dev), a library of conflict-free replicated data types. Each editor holds a local copy of the flow. Changes travel over a WebSocket to every other editor and to a server that stores the document.

Conflict-free means any two operations, applied in any order, produce the same result. There is no save button, and the server never overwrites your edit. You can edit offline, and your changes merge when you reconnect.

## What the document holds

- Every node, with its position, type, and settings.
- Every edge.
- Flow metadata, such as the name.

Each editor also broadcasts their cursor position and their selection, so you can see where other people are working.

The document does not hold:

- **Live values.** A Monitor node reads the local runtime. Your collaborator sees their own machine's values, or none.
- **The board connection.** Which board is plugged in belongs to one machine.
- **Your view.** Zoom and pan are yours.

## One flow, several machines, one board [#one-flow-multiple-machines-one-board]

Only one person can run a flow against a board, because there is one board.

- **Edit together, run on one machine.** The person with the board sees the LED light up. Everyone else sees the flow, with no live values.
- **You can work with no hardware at all.** Replace the Sense nodes with Constant, Oscillator, and Hotkey nodes. See [Collaborate without hardware](/docs/how-to/collaborate-without-hardware).
- **You cannot share a board over the network.** A serial port is local to one machine.

## Conflicts

If two people change the same setting on the same node at the same moment, Yjs keeps one value and discards the other, without reporting it. This is rare, because people work on different parts of a flow. When it happens, agree who edits what and redo the change.

If two people delete and re-add the same node at the same moment, you can end up with a duplicate. Delete the extra one.

## Roles

A flow has one owner, and every other person is an **editor** or a **viewer**. A viewer can pan, zoom, and select, and can change nothing. Only the owner can invite people, change roles, and delete the flow. See [Collaborate on a flow](/docs/how-to/collaborate-on-a-flow).

## Persistence and self-hosting

The Microflow server stores Yjs documents in PostgreSQL. The collaboration layer is open source. To self-host, run the server — Hono, a WebSocket, and PostgreSQL — and point Studio at it. See the [repository](https://github.com/xiduzo/microflow-t-stack).

## Limits to know

- **No version history.** Microflow exposes no way to return to yesterday's flow. [Export a file](/docs/how-to/save-and-share-a-flow) before a large change.
- **Documents grow.** A Yjs document accumulates an operation log as you edit. This is fine for a normal flow.
