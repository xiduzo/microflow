title: What is Microflow?
description: What each tool does, and when to use which.

Microflow is three tools. Use Studio alone, or add a design-tool plugin.

## Microflow Studio

The app you open to make hardware do something. It runs on Windows, macOS, and Linux, and in Chrome, Edge, or Opera.

Studio gives you a canvas and a library of **nodes**. Drag nodes on, connect them, configure them, and plug a board in over USB. Studio runs the flow on the board. You write no code and run no compiler.

Six categories of node cover everything Studio does:

- **Sense** — read the world: buttons, sensors, switches, a keyboard, a MIDI controller, the network.
- **Generate** — produce values from time, a pattern, or a fixed setting.
- **Shape** — transform values: maths, rescaling, smoothing.
- **Decide** — apply logic: comparisons, gates, change detection, delays.
- **Express** — act: LEDs, motors, sounds, a Figma variable, a language model.
- **Internal** — document a flow with a Note.

Most flows are a chain: Sense → Shape → Decide → Express.

Studio also generates an Arduino sketch from your flow, so a finished project can run on the board with Studio closed. See [Export an Arduino sketch](/docs/how-to/export-an-arduino-sketch).

## Microflow Hardware Bridge

A Figma plugin. It connects Figma variables to the outside world.

When your flow changes a value, the Bridge writes it into a Figma variable. When Figma changes a variable, the Bridge publishes the new value. Two workflows follow:

> Make a Figma prototype react to a real button. Studio reads the button and publishes it over MQTT. The Bridge sets the variable. Figma redraws.

> Make a real LED light up when someone taps a Figma button. The prototype changes a variable, the Bridge publishes it, and Studio's Figma node drives the LED.

The Bridge knows nothing about hardware. It speaks MQTT. Studio bridges MQTT and your board, and so could anything else that speaks MQTT.

## Microflow for Penpot

The same idea for [Penpot](https://penpot.app), the open-source design tool. It maps Penpot design tokens instead of Figma variables. It is experimental.

## How they fit together

<img src="/diagrams/studio-mqtt-bridge-figma.svg" alt="The pipeline: an Arduino and its components, over USB and Firmata, into Microflow Studio, over MQTT, into the Hardware Bridge plugin, into variables in a Figma file's MHB collection." />

MQTT is the pipe between Studio and a plugin. Both ends connect to a broker, and you can [run your own](/docs/how-to/run-your-own-mqtt-broker).

- **Studio works alone.** You need neither plugin.
- **A plugin works with anything that speaks MQTT**, not only with Studio.
- **All three are free and open source**, and run locally.

## When to use which

| Project | Tools |
| --- | --- |
| A thing that responds to physical inputs | Studio |
| A smart-device prototype with no hardware yet | Figma and the Bridge |
| A demo of connected-product behaviour | Studio, the Bridge, and Figma |
| A workshop teaching electronics without code | Studio |
| A Figma prototype wired to a button on a 3D-printed model | Studio, the Bridge, and Figma |

If you are unsure, start with Studio. Add a plugin later.
