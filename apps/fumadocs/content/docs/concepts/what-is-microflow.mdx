title: What is Microflow?
description: A working mental model of Studio, the Figma and Penpot plugins, and how they relate.

"Microflow" is not one program. It is Microflow Studio plus two design-tool plugins: the Hardware Bridge for Figma, and the [Microflow plugin for Penpot](/docs/microflow-penpot-plugin). This page explains what each one does and why a project might use Studio alone or together with a plugin.

## Microflow Studio

The app you open when you want to make hardware do something. It runs in your browser at [microflow.tech](https://microflow.tech) and as a desktop app.

Studio gives you a **canvas** — a blank infinite grid — and a library of building blocks called **nodes**. You drag nodes onto the canvas, connect them, and configure them. Plug in an Arduino-compatible board over USB and Microflow runs your flow on it. No code, no compilation, no Arduino IDE.

Six categories of node cover everything Studio can do:

- **Sense** — read from the world (buttons, sensors, switches).
- **Generate** — produce values from time, intervals, or constants.
- **Shape** — transform values (math, smoothing, mapping).
- **Decide** — apply logic (comparisons, gates, counters, delays).
- **Express** — drive the world (LEDs, motors, sounds).
- **Internal** — observe (Monitor) and document (Note) your flow.

Most flows are a chain like: Sense → Shape → Decide → Express. The Generate and Internal categories slot in wherever they are useful.

Studio runs **everywhere**: in Chrome or Edge, and as a desktop app for macOS, Windows, and Linux. The Arduino runs StandardFirmata; Studio sends commands to it over USB. The runtime that executes your flow lives inside Studio, not on the Arduino. When a project needs to run without a computer, Studio can export the flow as a standalone Arduino sketch instead — see [The microcontroller bridge](/docs/concepts/the-microcontroller-bridge#2-the-board-is-not-autonomous).

## The design-tool plugins

The [Microflow Hardware Bridge](/docs/microflow-hardware-bridge) is a Figma plugin. The [Microflow plugin for Penpot](/docs/microflow-penpot-plugin) does the same job in Penpot. Both speak the same protocol.

A plugin does one thing: it links the values in a design file to the outside world. In Figma these are the variables in the **MHB** collection; in Penpot, the tokens in the **MHB** token set. When your flow changes a value, the plugin writes it into the variable. When you change the variable in the design file, the plugin sends the new value out.

In Studio, the [Design variable](/docs/microflow-studio/nodes/express/figma) node is the other end of the link:

> "Make my design react to a real button press" — Studio reads the button, the Design variable node sends the value, the plugin sets a variable, and the design file redraws.

> "Make a real LED follow a value in my design" — you change a variable in the file, the plugin sends it, and the Design variable node passes it on to the LED.

The plugins run only while the file is open in the editor. Neither Figma nor Penpot runs plugins in a prototype, so the link is to the design file, not to a running prototype.

A plugin does not know anything about hardware. It just speaks MQTT. Microflow Studio is what connects MQTT to your Arduino, but anything else that speaks MQTT (a Raspberry Pi, an ESP32, a custom script) can also read and change the same variables.

## How they fit together

<img src="/diagrams/studio-mqtt-bridge-figma.svg" alt="Pipeline: Arduino + components ↔ USB/Firmata ↔ Microflow Studio ↔ MQTT ↔ Hardware Bridge Figma plugin ↔ variables ↔ Figma file MHB collection. The Penpot plugin takes the place of the Figma plugin in the same way." />

The pipe between Studio and a plugin is **MQTT**, an off-the-shelf messaging protocol. Both connect to the same MQTT broker and use the same **Bridge ID**. The plugins start on a free public broker, and you add the same broker in Studio. You can also [run your own](/docs/how-to/run-your-own-mqtt-broker).

Importantly:

- **Studio works on its own.** You do not need a plugin, Figma or Penpot.
- **A plugin works without Studio.** Anything that speaks MQTT can read and change the variables.
- **They are free and open source.** With your own broker, the values they send do not have to leave your network.

## When to use which

| Project | Tool(s) |
| --- | --- |
| Make a thing that responds to physical inputs | Studio |
| Make a design react to a real sensor or button | Studio + a plugin + Figma or Penpot |
| Drive real hardware from values in a design file | Studio + a plugin + Figma or Penpot |
| Try a design's behaviour before the hardware exists | Studio (Generate nodes) + a plugin + Figma or Penpot |
| Run a workshop teaching electronics without code | Studio |

When you are unsure: start with Studio. A plugin is an optional layer you can add at any point.
