## A flow is a directed graph

A **flow** is the whole diagram on the canvas. Each box is a **node**. Each line is an **edge**. An edge runs one way: from a node's output, on the right, to another node's input, on the left.

## What a node holds

- **Settings** — fixed configuration, such as a pin number, a range, or a maths operation. Settings are stored with the flow.
- **Inputs** — the handles on the left. Some nodes have several, each with its own meaning.
- **Outputs** — the handles on the right. Some nodes emit on several, such as a [Button](/docs/microflow-studio/nodes/sense/button) with `event`, `true`, `false`, `hold`, and `value`.
- **Behaviour** — what the node does when an input arrives.

Most nodes hold no state. A few do: a [Counter](/docs/microflow-studio/nodes/generate/counter) holds a count, and a [Smooth](/docs/microflow-studio/nodes/shape/smooth) holds a window of recent readings.

## Values move on events, not on a clock

Microflow is event-driven. No global clock scans the nodes.

- A Sense node fires when its input changes. For an analog input, it fires when the change is large enough to matter.
- A Generate node fires on its own schedule, such as an Interval, or once at startup, such as a Constant.
- Every other node fires when one of its inputs changes.

When a node fires, the value travels down every outgoing edge, and each downstream node fires in turn.

<img src="/diagrams/event-propagation.svg" alt="An event chain: the physical world, a Button node, a Smooth node, a Compare node, an LED node, and back to the physical world. One physical event triggers one chain." />

A node's `value` output is deduplicated: it fires only when the value changes. Momentary handles such as `event`, `true`, `false`, and `hold` always fire, because they mark a moment rather than a state.

Three consequences:

- **A flow with no Generate node and no sensor activity does nothing.** No event means no work.
- **A [Monitor](/docs/microflow-studio/nodes/express/monitor) node passes its value straight through.** You can add one anywhere in a chain without breaking it.
- **A node never blocks.** Firing a node schedules the nodes after it.

## What travels on an edge

| Kind | Looks like | Examples |
| --- | --- | --- |
| **Digital** | `0` or `1` | A button press, a switch state |
| **Analog** | A number in a range | A potentiometer, `0`–`1023`. Brightness, `0`–`255`. |
| **Boolean** | `true` or `false` | The output of a Compare or a Gate node |
| **Text** | A string | An MQTT message, an LLM answer |
| **Structured** | An array or an object | A colour, a strip of pixel colours |

Most nodes accept anything number-like. The [Function](/docs/microflow-studio/nodes/shape/function) node is stricter, because your own code runs inside it.

Handles are drawn by kind: `●` value, `◆` event, `■` state, `▶` command. See [Edges](/docs/microflow-studio/edges).

## Editing a running flow

You can change a flow while it runs. The runtime keeps up.

- **Add a node.** It stays idle until an edge reaches it.
- **Add an edge.** The upstream node's next output travels through it.
- **Remove a node.** Its pin is released, and the nodes after it stop receiving.
- **Change a setting.** The node uses the new setting on its next event.

That is why building feels iterative. Leave the board running and change the flow around it.

## Where the runtime lives

The executor is a Rust runtime inside Studio. It turns your flow into pin operations on the connected board, runs the I/O loops, and feeds events back to the canvas. The board does not know your flow exists — it answers Firmata commands. See [The microcontroller bridge](/docs/concepts/the-microcontroller-bridge).
