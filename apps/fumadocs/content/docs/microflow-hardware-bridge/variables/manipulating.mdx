---
title: Using variables with Microflow
description: Read and change your Figma variables from a Microflow Studio flow, in both directions.
---

You use your MHB variables in Studio through the [Design variable](/docs/microflow-studio/nodes/express/figma) node. One node links to one variable. Add a node for each variable you want to use.

---

## Link a variable to a node

1. Run the plugin in your Figma file. Check that its **MQTT** dot is green.
2. In Studio, add a **Design variable** node to your flow.
3. In the node settings, select the **Broker** that the plugin uses.
4. Check that the plugin uses the node's Bridge ID. See [MQTT settings](/docs/microflow-hardware-bridge/mqtt#the-bridge-id).
5. Open the node's **variable** list and pick your variable. When a Figma and a Penpot plugin are both connected, the names end in "(Figma)" or "(Penpot)".

The node's inputs change to match the type of the variable.

## Hardware → Figma

Connect a value to one of the node's inputs. The plugin writes the new value into the variable, and Figma redraws every layer that uses it.

| Variable type | Inputs | What they do |
| --- | --- | --- |
| Boolean | `true`, `toggle`, `false` | Set the variable to true, flip it, or set it to false. |
| Number | `set`, `increment`, `decrement`, `reset` | `set` uses the incoming number. `increment` and `decrement` add or subtract the incoming number (`true` counts as 1). `reset` sets 0. |
| String | `set` | Set the variable to the incoming text. |
| Color | `red`, `green`, `blue`, `opacity` | Change one channel. Red, green and blue take 0–255. Opacity takes 0–100. |

**Example:** Potentiometer → Map (0–1023 to 0–100) → the `set` input of a Number variable. Studio ships this flow as the **Sensor to Figma or Penpot** template.

A value that does not fit the variable's type is dropped. For example, the text `hello` cannot set a Number variable.

## Figma → hardware

Change the variable in Figma. The plugin checks for changes four times a second and sends the new value. The node sends it out of its `change` output. Connect `change` to the rest of your flow.

**Example:** a Number variable from 0 to 100 → Map (0–100 to 0–255) → LED on pin 9. Studio ships this flow as the **Figma or Penpot to LED** template.

The `change` output fires for every new value: a change made in Figma, and a change made through the node's own inputs.

## Advanced: MQTT topics

Other MQTT clients can use the same variables, for example a script, a Raspberry Pi or your own firmware. The plugin's **Variables** page has two copy buttons for each variable: the topic that changes it, and the topic that carries its value.

Every topic starts with `microflow/{bridgeId}/{client}/`. `{client}` is the sender: `figma`, `penpot`, or `app` for Studio.

| Topic | Sender | Payload | Retained |
| --- | --- | --- | --- |
| `{tool}/status` | plugin (last will) | `connected` / `disconnected` | yes |
| `{tool}/variables` | plugin | `{[id]: {id, name, resolvedType}}` | yes |
| `{tool}/variable/{wireId}` | plugin | JSON value | no |
| `app/status` | Studio | `connected` / `disconnected` | yes |
| `app/variables/request` | Studio | empty | no |
| `app/variable/{wireId}` | plugin, answering a request | JSON value | no |
| `app/variable/{wireId}/set` | Studio | JSON value | no |

`{tool}` is `figma` for this plugin. `{wireId}` is the variable's ID in a form that is safe in a topic: the Figma ID `VariableID:1:25` becomes `1-25`.

For example, with the Bridge ID `calm_lynx_4821`:

```sh
# Print every value change of variable 1:25
mosquitto_sub -h test.mosquitto.org -t microflow/calm_lynx_4821/figma/variable/1-25

# Set variable 1:25 to 42
mosquitto_pub -h test.mosquitto.org -t microflow/calm_lynx_4821/app/variable/1-25/set -m 42
```

Values are not retained. A new subscriber gets a value only when it next changes. To get all current values at once, publish an empty message to `microflow/{bridgeId}/{you}/variables/request`, where `{you}` is a name for your client other than `figma` or `penpot`. The plugin answers on `microflow/{bridgeId}/{you}/variable/{wireId}`.

### Payloads

The plugin reads a payload as JSON when it can, and as plain text when it cannot. Then it converts the value to the variable's type:

| Type | Accepted payloads |
| --- | --- |
| Boolean | `true` / `false`, `on` / `off`, `yes` / `no`, `1` / `0`. Any other number is true unless it is 0. |
| Number | `42`, `-1.5`, `3,5`, `12px` (the unit is ignored), `true` (becomes 1). |
| String | Any text or number. |
| Color | `{"r":1,"g":0,"b":0,"a":1}` (each channel 0–1), `#ff0000`, `#ff000080`, `rgb(255, 0, 0)`, `rgba(0 0 255 / 0.5)`. |

The plugin drops a value that does not fit. It sends colors as `{"r", "g", "b", "a"}` with each channel from 0 to 1.

A `set` message for an ID that the plugin does not own is ignored. This lets the Figma and Penpot plugins share one Bridge ID.

## Limitations

- **Editor only.** Figma does not run plugins in prototypes. The bridge links hardware to the variables of a file that is open in the editor. A change made in a running prototype does not reach the plugin.
- **Keep the plugin open.** When you close the plugin, the link stops. Studio then shows "Figma plugin is not connected" on the node.
- **Default mode only.** Other modes of a collection are not linked.
- **Shared brokers.** On a public broker, the Bridge ID is the only thing that keeps your values apart from other people's. Use your [own broker](/docs/how-to/run-your-own-mqtt-broker) for anything private.
