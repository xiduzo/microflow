The plugin and Microflow Studio send messages to each other through an **MQTT broker**, a server that passes messages between programs. They must use the same broker and the same **Bridge ID**.

Click the gear icon on the plugin's home screen to open the MQTT settings. Click **Save MQTT settings** to connect. The plugin does not connect until you have saved a Bridge ID.

## Settings

| Setting | What it does |
| --- | --- |
| **Bridge ID** | Pairs the plugin with Studio. It must be the same as the Bridge ID that Studio shows. Use 5 to 64 characters: letters, digits, `-` and `_`. The dice button makes a random one. |
| **Broker URL** | The broker to connect to, as `[protocol://]host[:port][/path]`. The default is `wss://test.mosquitto.org:8081/mqtt`. |
| **Username** | Only if your broker needs one. |
| **Password** | Only if your broker needs one. |

---

## The Bridge ID

The Bridge ID is part of every message the plugin and Studio send. Studio and the plugin find each other only when their Bridge IDs are the same.

To find Studio's Bridge ID, add a [Design variable](/docs/microflow-studio/nodes/express/figma) node to a flow:

- While Studio knows no variables yet, the node shows its Bridge ID.
- The node settings have a **bridge ID** field and a **copy bridge ID** button.

Studio makes its Bridge ID from your account name, with unsupported characters replaced by `_`. For example, "Sander Boer" becomes `Sander_Boer`. When you are not signed in, or your name gives fewer than 5 characters, Studio uses a random ID for your device, such as `calm_lynx_4821`. You can type your own ID in the **bridge ID** field. Clear the field to go back to the default.

If you make a new ID with the dice button in the plugin, type the same ID into Studio's **bridge ID** field.

## The broker URL

- The plugin connects over WebSockets: `wss://` (encrypted) or `ws://`. It cannot use `mqtt://` or `mqtts://`.
- Use `wss://` for a broker on another computer. The plugin runs inside Figma's HTTPS page, and browsers block unencrypted `ws://` connections from such pages.
- If you leave out the protocol, the plugin uses `wss://`. If you leave out the port, it uses `8883` for `wss://` and `1883` for `ws://`. If you leave out the path, it uses `/mqtt`.

Studio must connect to the same broker. Add it in Studio under **Configuration → MQTT**. The simplest setup uses the same URL in both tools. Studio in the browser also needs a `ws://` or `wss://` URL.

## The default broker

The default broker is the free public test server at `test.mosquitto.org`. It needs no account, so it is the fastest way to try the bridge.

<Callout type="warn" title="The default broker is public">
Anyone can read and send messages on a public broker. Anyone who knows or guesses your Bridge ID can read your variables and change them. Use the public broker for learning and prototyping. For anything private, [run your own broker](/docs/how-to/run-your-own-mqtt-broker).
</Callout>

## Running your own broker

Any MQTT broker with a WebSocket listener works. Follow [Run your own MQTT broker](/docs/how-to/run-your-own-mqtt-broker), then enter its URL in both the plugin and Studio.

For a broker that other computers reach over a network, set up TLS so the plugin can use `wss://`. Tools like [Caddy](https://hub.docker.com/_/caddy) or [Nginx](https://hub.docker.com/_/nginx) can add TLS in front of a local broker.

## Where the settings are stored

The plugin keeps its settings, including the password, in Figma's client storage on your computer. They are stored in plain text.
