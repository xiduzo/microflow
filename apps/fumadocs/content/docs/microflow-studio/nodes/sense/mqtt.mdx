The MQTT node connects your flow to an MQTT broker — a message-passing server. Its **direction** setting decides what it does:

- **subscribe** (the default) — the node listens to a topic and sends each message it receives out of its output.
- **publish** — the node sends each value that arrives at its input to a topic.

Only a direction of exactly `publish` publishes. Any other value, or none, subscribes. This holds in Studio and in the exported Arduino sketch.

<Callout title="Linking to Figma or Penpot? Use the Design variable node">
To read or change a variable in a Figma or Penpot file, use the [Design variable](/docs/microflow-studio/nodes/express/figma) node. It works with the Figma and Penpot plugins, and you do not need to know their topics.
</Callout>

Before you use the node, add a broker under **Configuration → MQTT** in Studio. A broker has a name, a URL, and an optional username and password. In the browser, Studio can only reach a broker over `ws://` or `wss://`. The desktop app also accepts other schemes, such as `mqtt://`.

<Callout type="warn" title="Your broker must speak MQTT 5">
Studio connects to every broker with MQTT 5, in the browser, in the desktop app and in the Connection Console. A broker that speaks only MQTT 3.1.1 refuses the connection, and Studio cannot use it.

- **Works:** Mosquitto 1.6 and later (including `test.mosquitto.org`), HiveMQ (including `broker.hivemq.com`), EMQX, VerneMQ.
- **Does not work:** brokers that speak only MQTT 3.1.1, such as Adafruit IO and Azure IoT Hub.

Not sure? Check your broker's documentation for "MQTT 5", or see [MQTT can't connect](/docs/troubleshooting/mqtt-cant-connect).
</Callout>

What you type into a broker's settings applies 500 ms after your last keystroke, or at once when you run a console command, close the form, or hide or leave the page. Adding or removing a broker, and choosing the default broker, apply at once.

<Callout type="warn" title="Public brokers mean public data">
Anyone can read and send messages on a public broker such as `test.mosquitto.org`. Do not send passwords, personal information, or anything sensitive through it. It is fine for testing and prototyping.
</Callout>

## Inputs and outputs

The handles follow the **direction** setting:

- **publish** — one input, **trigger**. Each value that arrives is published to the topic.
- **subscribe** — one output, **value**. It fires with each message that arrives on the topic.

## Subscribing with wildcards

When the node subscribes, its **topic** can be a topic filter with wildcards. This works in the browser and in the desktop app.

- `+` matches exactly one level. `sensors/+/temperature` matches `sensors/kitchen/temperature`, not `sensors/kitchen/oven/temperature`.
- `#` matches the level before it and every level below it. It must be the last level. `sensors/#` matches `sensors`, `sensors/kitchen` and `sensors/kitchen/oven`.
- A filter that starts with `+` or `#` does not match topics that start with `$`, such as `$SYS/…`.
- Shared subscriptions (`$share/<group>/<filter>` and `$queue/<filter>`) deliver messages too.
- A filter that is not valid, such as `sensors/#/temperature` or `sensors+`, matches nothing.

When a message matches the topics of several MQTT nodes in a flow, each of those nodes gets it once. Studio asks the broker to say which subscriptions a message is for (MQTT 5 subscription identifiers). A broker that does not do this gets its messages routed by topic: there a node can get a message once for each copy the broker sends.

A topic you publish to cannot hold a wildcard and cannot be empty. A publish to such a topic is not sent.

## Settings

| Setting | What it does |
| --- | --- |
| **Broker** | Which of your brokers to use |
| **direction** | `subscribe` to receive messages, `publish` to send them |
| **topic** | The topic to publish to, or the topic filter to subscribe to |
| **QoS** | The delivery guarantee: at most once (0), at least once (1, the default), or exactly once (2) |
| **retain** | Publish only. Asks the broker to keep the last message for new subscribers |

## Arduino sketch export

When you export a flow as an Arduino sketch for an ESP32, the sketch connects to the broker itself over Wi-Fi, with plain MQTT (port `1883` by default). The node needs a board with Wi-Fi: for a board without it, such as the Uno, generating the sketch gives a warning.

- **publish** — each value that reaches **trigger**, from any connected node and the same value again included, is published as Studio writes it: a number as its shortest exact digits without an exponent (`1`, `0.1`, `NaN`, `inf`), `true` or `false`, and text as it is.
- **subscribe** — **value** fires with each message, as a number. A message that is a number gives that number, `true` gives `1`, and any other text gives `0`. In Studio, `true` and `false` stay booleans and other text stays text.
