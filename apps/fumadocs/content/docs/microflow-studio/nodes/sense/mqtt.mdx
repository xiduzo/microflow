The MQTT node connects your flow to an MQTT broker, which is a message-passing server. Set **Direction** to `subscribe` to receive messages, or to `publish` to send them.

Use it to reach anything that speaks MQTT: another Microflow flow, a Raspberry Pi, a home automation system, or your own script.

To reach a Figma or Penpot file, use the [Figma](/docs/microflow-studio/nodes/express/figma) node instead. It handles the addressing for you.

<Callout type="warn" title="Broker configuration is desktop-only">
The browser build cannot add or edit brokers.
</Callout>

## Inputs

- **`trigger`** — Publish the current value to the topic. `publish` direction only.

## Outputs

- **`value`** — The last message received on the topic. `subscribe` direction only.

## Settings

- **Direction** — `subscribe` to receive, `publish` to send. Default `subscribe`.
- **Broker** — Which configured MQTT broker to use. Add brokers under **Configuration → MQTT**.
- **Topic** — The topic to publish to or subscribe to.
- **QoS** — Quality of service. `0` delivers at most once, `1` at least once, `2` exactly once. Default `1`.
- **Retain** — Ask the broker to keep the last message, so a new subscriber receives it at once. Default `false`.

## Tips

- **Use a WebSocket URL for the broker.** Microflow accepts `ws://` and `wss://` only. See [MQTT will not connect](/docs/troubleshooting/mqtt-cant-connect).
- **Test a broker before you build on it.** The **Test Client** on the MQTT configuration page subscribes and publishes without a flow.
- **Topics are case sensitive.** `home/Light` and `home/light` are different topics.
- **A public broker is public.** Anyone can read and write your topics. Use one for a demo, not for anything you care about.
