The Function node lets you write custom JavaScript that runs each time a value arrives. It is the escape hatch for transformations that are too specific or complex for the built-in nodes.

Your code lives inside a `trigger(input)` wrapper. Whatever you `return` becomes the output value.

```ts
function trigger(input: unknown) {
  // your code here
  return input;
}
```

## Inputs

- **trigger** (left handle) — the incoming value, available as `input` inside your code
- **Template variables** (bottom handles) — use `{{varName}}` anywhere in your code to create additional input handles. Each connected value is substituted at runtime before execution

## Output

- **value** (right handle) — emits what your function returns, each time the result differs from the value the node holds. The node starts at `0`, so a first `true` or `false` is always sent.

### Template variables

Write `{{brightness}}` or `{{threshold}}` in your code and a new handle appears on the bottom of the node. Connect any value-producing node to it and the placeholder is replaced with the live value at runtime.

```ts
// Two template variables: {{min}} and {{max}}
if (typeof input !== "number") return 0;
return Math.min(Math.max(input, {{min}}), {{max}});
```

Template variables inside comments (`//` or `/* */`) are ignored and will not create handles.

## Built-in utility functions

Because `input` is typed as `unknown`, safely handling the incoming value requires boilerplate. The Function node provides a set of built-in sanitization helpers that are always available inside your code — no imports needed. They are designed to make type coercion and validation concise and safe.

### `toNumber(value, fallback?)`

Coerce any value to a number. Returns `fallback` (default `0`) when the result would be `NaN`.

```ts
const n = toNumber(input);       // 0 if input is not numeric
const n = toNumber(input, -1);   // -1 as fallback
```

### `toString(value)`

Coerce any value to a string. Objects and arrays are JSON-stringified.

```ts
const s = toString(input);       // always a string
```

### `toBool(value)`

Coerce any value to a boolean using JavaScript truthiness, with special handling: the strings `"false"`, `"0"`, and `""` return `false`.

```ts
const b = toBool(input);
```

### `ensureRange(value, min, max, fallback?)`

Return the value as a number if it falls within `[min, max]`. Otherwise return `fallback` (default `min`).

```ts
const safe = ensureRange(input, 0, 255);       // clamps to 0 if out of range
const safe = ensureRange(input, 0, 255, 128);  // 128 as fallback
```

### `oneOf(value, allowed, fallback)`

Return the value if it is strictly equal to one of the `allowed` entries, otherwise return `fallback`.

```ts
const mode = oneOf(input, ["on", "off", "blink"], "off");
```

### `isValid(value)`

Return `true` if the value is not `null`, `undefined`, or `NaN`.

```ts
if (!isValid(input)) return 0;
```

### Example: combining utilities

```ts
// Safely read a sensor value, clamp it, and pass it on
if (!isValid(input)) return {{fallback}};
return ensureRange(input, {{min}}, {{max}});
```

## Runtime

User code executes in an embedded JavaScript engine (boa) inside the flow runtime — natively in the desktop app, and compiled to WebAssembly in the browser. There are no network round-trips.

Two limits stop runaway code from freezing the runtime:

- **Loops:** one function call can run at most 10,000 loop iterations (`for`, `while`, `do…while`, `for…in`, `for…of`). The count is shared by every loop in that call. A function you call from your code gets its own count of 10,000.
- **Recursion:** functions can nest at most 512 calls deep.

Past a limit, your code throws an error. If your code throws an error, the node's output keeps its last successful value and nothing new is sent, so the rest of the flow keeps running.

## On the board

When you export a flow as an Arduino sketch, the Function node's code is translated to C++. The board runs a subset of JavaScript, with JavaScript's rules:

- `const`, `let` and `var` bindings, then one `return`. Separate statements with `;` or a line break.
- `input`, when it is a number or `true`/`false`, and any name bound before.
- Decimal numbers (`5`, `2.5`, `.5`, `1e3`), `true` and `false`.
- `+ - * / % **`, unary `- + !`, `> < >= <= == != === !==`, `&&`, `||`, `? :` and parentheses.
- `Math.floor`, `ceil`, `round`, `abs`, `sqrt`, `pow`, `min` and `max`, and the helpers `toNumber`, `toBool`, `isValid` and `ensureRange`.

These behave as in Studio: `&&` and `||` give back one of their operands, `%` keeps the sign of the left side, `Math.round` rounds a half up, `NaN` counts as false, `Math.min` and `Math.max` take any number of arguments, and `===` between a number and a boolean is `false`.

The board does not run other code. That includes:

- an `input` that is text, a colour or a list;
- a result that is a number for some inputs and `true`/`false` for others;
- numbers such as `010` or `0x10`;
- `++` and `--`;
- a name declared twice;
- a line break right after `return`;
- loops, objects, functions, text, block comments, `{{var}}` template variables and other calls.

For such code, generating the sketch gives a warning that names the reason, and the sketch has a note in its place. On the board the node then never runs and never emits.

Only the first node connected to **trigger** is used on the board. Other connections are left out, with a note in the generated code.

On AVR boards, such as the Uno, a number is a 32-bit float. Results agree with Studio to about seven digits.
