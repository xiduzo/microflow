## Set up before you record

- Use the desktop app. AI provider configuration is desktop-only.
- Install Ollama and pull a small model in advance. Say on camera that you did.
- Stop Ollama before recording. Starting it is part of the script, and so is the failure when it is not running.

## Script

### 0:00 — What this is for

**Screen:** The finished flow: Button → LLM → Monitor.

**Narration:**
> "A language model as a node. Press a button, get a sentence back. It runs on your machine, so nothing you sense or type leaves the room, and it works with no internet. It is also slow compared to everything else in Microflow, so it belongs at the end of a flow, never inside a control loop."

### 0:40 — Start Ollama

**Screen:** Terminal. Start the Ollama server, then run `ollama list`.

**Narration:**
> "Microflow ships no model. It talks to one you are already running, and Ollama is the easiest of those. Start it, and check your model is there. I pulled this one before recording, because that download is several gigabytes."

**On-screen text:** `http://localhost:11434`

### 1:10 — Add the provider

**Screen:** **Configuration → LLM** → **Add Provider**. Name `Local Ollama`, base URL `http://localhost:11434`, no API key. Submit, then run the test. The success message appears.

**Narration:**
> "Configuration, then LLM. Add a provider. The base URL is localhost, colon, one-one-four-three-four, which is Ollama's default. No API key: it runs on your own machine. Save it, then test it. That test tells you the problem is not Studio, before you go looking in your flow."

**On-screen text:** `Base URL http://localhost:11434 · no API key`

### 2:00 — Failure: Ollama stopped

**Screen:** Stop Ollama in the terminal. Press test again. The failure message appears with its reason. Zoom in. Restart Ollama and test again.

**Narration:**
> "Stop the server and test again. You get a connection error with the reason attached. You will see this if Ollama is not running, if the port is wrong, or if you pointed at a machine that is asleep."

**On-screen text:** `[provider test failed — connection refused]`

### 2:40 — The LLM node

**Screen:** `Cmd/Ctrl + K`, add **LLM**, under **Express**. In its settings: select the provider, type the model name, then fill in **System** (`You are a museum guide. Answer in one short sentence.`) and **Prompt** (`Someone just walked up to the exhibit. Greet them.`).

**Narration:**
> "The LLM node lives under Express, because it is something your flow does. Select the provider and name the model. The system prompt sets the character and the answer length. Say how long you want the answer, or you get an essay. The prompt below it is the request."

### 3:30 — Trigger it from hardware

**Screen:** Add a **Button** node on pin 6. Connect Button `event` to LLM `trigger`. Add a **Monitor** node in `raw` mode on the `value` output. Press the button. Do not cut. Wait for the text.

**Narration:**
> "It needs a trigger. Connect a button's event to the trigger input, and hang a Monitor in raw mode on the value output. Press the button. Now we wait, because this is what it actually feels like."

<Callout type="warn" title="Do not cut the wait">
Show the real latency. A viewer who expects an instant answer assumes it is broken at four seconds.
</Callout>

### 4:20 — Thinking, done, and error

**Screen:** Zoom on the node's four outputs. Connect `thinking` to an LED node's `true` and `false` inputs. Press the button again. The LED is on while the model works.

**Narration:**
> "That wait is why the node has four outputs. Value is the text. Thinking is true from the trigger until the answer arrives, so wire it to a light and your prototype shows it is working. Done fires once, when the answer is complete, and that is what you chain the next step to. Error fires when the model could not be reached."

**On-screen text:** `value · thinking · done · error`
