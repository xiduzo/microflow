## Set up before you record

- Two machines, or one machine and a second browser profile. Two distinct demo accounts — `Demo` and `Guest` — with different avatar colours.
- Capture both screens. The whole video is a split screen.
- A flow named `Workshop` with three or four nodes already on the canvas.

## Script

### 0:00 — Two people, one flow

**Screen:** Split screen, both windows on the same flow. Both cursors move; the guest drags a node and it moves on the host's screen at the same time.

**Narration:**
> "Two people, two computers, one flow. No files sent back and forth, and nobody overwriting anybody."

### 0:20 — Invite an editor

**Screen:** Host: dock → flow settings → **Collaborators**. Type the guest's email, choose the **editor** role, send. The row appears marked **Invited**. Cut to the guest accepting and opening the flow.

**Narration:**
> "On the host's side, open the flow's settings and find Collaborators. Enter an email address and select a role. An editor can change the flow. A viewer can only look. Until they accept, the row reads Invited, which is also how you spot a wrong address."

**On-screen text:** `Settings → Collaborators → role: editor`

### 1:00 — What the guest sees

**Screen:** Split screen. The guest adds a node; it appears on the host's canvas. The host edits a setting; the guest's node updates. Both coloured cursors visible with names attached.

**Narration:**
> "Every edit lands on both screens as it happens. The coloured cursor with a name on it is the other person, and it tells you what they are about to touch. If you both edit the same node at the same moment, one change wins. There is no lock and no merge dialog."

### 1:45 — The viewer role

**Screen:** Host changes the guest's role to **viewer**. Cut to the guest's window: a **View only** badge appears in the corner. The guest tries to drag a node — it does not move — and tries to draw an edge — the handles do not respond.

**Narration:**
> "Switch them to viewer and their window changes at once. A View only badge appears in the corner, nodes will not move, edges will not connect, and the delete key does nothing. They can still pan, zoom, and select, so they can follow the flow without changing it. That is the classroom role."

**On-screen text:** `[View only]`

### 2:25 — Whose board is it?

**Screen:** The host's sidebar shows a connected port. The guest's sidebar shows **No microcontroller connected**. The host presses the physical button. The host's Monitor node reacts. The guest's Monitor node does not.

**Narration:**
> "The flow is shared. The hardware is not, and neither are the live values. My board is plugged into my machine, so my collaborator's sidebar says nothing is connected — which is correct. Their Monitor stays empty, because it reads their runtime, not mine. To work from that side, swap the sensors for Constant and Hotkey nodes. The how-to under this video shows how."

### 3:00 — Revoking access

**Screen:** Host: change the role back to editor, then withdraw a pending invite from the list. Show the toast confirmations.

**Narration:**
> "A role change takes effect at once. You can withdraw a pending invite before it is accepted. Only the owner, who created the flow, can invite people, change roles, or delete it."

## Deliberate failure

None staged. The viewer-role restrictions at 1:45 serve the same purpose: show the thing that looks broken and name it as intended behaviour.

## Post-production notes

- Label each half of the split screen with the account name for the entire runtime. Viewers lose track otherwise.
- Do not cut between an action and its appearance on the other screen. The simultaneity is the demonstration.
- Blur real email addresses. Use `guest@example.com`.
