## Set up before you record

- A clean machine or a fresh user account, so the install is genuinely first-run.
- Label both cables underneath, so you never hunt for the right one on camera.
- The Arduino IDE installed and closed. It opens later in the series.
- Chrome or Edge with the serial permission for the Studio origin revoked, so the prompt appears.

## Script

### 0:00 — What you need

**Screen:** Overhead: Uno, USB cable, laptop.

**Narration:**
> "You need a board — this is an Uno, and a Nano or an ESP32 works too — a USB cable that carries data, and a computer."

**On-screen text:** `Supported: Arduino Uno · Arduino Nano · ESP32`

### 0:25 — Download and install

**Screen:** The releases page. Download the build for this platform, install it, and launch. Cut the copy progress to two seconds.

**Narration:**
> "Take the build for your operating system from the releases page. On a Mac, drag it to Applications. On Windows, run the installer. Open it, and you land on an empty canvas with the sidebar down the left."

### 1:10 — Plug the board in

**Screen:** The sidebar reads **No microcontroller connected**. Cut to the hand plugging in the cable. Cut back to the sidebar and hold, uncut, through the whole sequence.

**Narration:**
> "Nothing is connected, and the sidebar says so. Plug the board in and watch that button. Connecting, while Studio finds the port. Then, the first time you use a board, Flashing firmware, for up to a minute. Leave it alone while it does that. When it finishes you get the name of the serial port, and that is your signal that everything is ready."

**On-screen text, timed to each state:** `Connecting` → `Flashing firmware` → `/dev/cu.usbmodem14201`

<Callout type="warn" title="Do not cut the flashing wait">
Show the real duration. Speed it up 4× with a visible badge if it runs past 20 seconds. Cutting it teaches people to panic and unplug.
</Callout>

### 2:00 — What the firmware step was

**Screen:** A still of the connected sidebar.

**Narration:**
> "Your board arrives knowing nothing about Microflow. That step puts a small program on it whose only job is to take orders over USB: set this pin high, tell me when that pin changes. It happens once per board."

### 2:25 — Failure: the wrong cable

**Screen:** Unplug. The sidebar returns to **No microcontroller connected**. Plug in the charge-only cable. Hold for ten uncut seconds. Click the question mark beside the status; the troubleshooting page opens. Cut back, swap to the data cable, and the status walks to connected.

**Narration:**
> "Here is the failure you are most likely to hit. This cable came with a pair of headphones and carries power only. The board lights up, so it looks alive, but the computer never sees a serial port. That question mark opens the troubleshooting page. If a cable came with a phone, a battery pack, or headphones, try another one first."

**On-screen text:** `[status unchanged for 10s — charge-only cable]`

### 3:05 — The browser route

**Screen:** Chrome, Studio in a tab, sidebar showing **Connect board**. Click it. The browser's port chooser opens. Select the Arduino, confirm, and watch the same states.

**Narration:**
> "You do not have to install anything. In Chrome, Edge, or Opera the same app runs in a tab. The difference is that a browser will not touch a serial port until you say so, so the button reads Connect board. Click it, pick your board, and from there it behaves like the desktop app. In Firefox or Safari the button tells you to switch, because those browsers cannot reach a serial port at all."

**On-screen text:** `Web Serial: Chrome · Edge · Opera`

### 3:45 — Recap

**Screen:** Split screen: desktop app and browser tab, both connected.

**Narration:**
> "Two ways in, one thing to look at. A port name in the sidebar means you are connected, and every flow you build will run on that board."

## Deliberate failure

The charge-only cable at 2:25. Use a real one, and show ten uncut seconds.

## Post-production notes

- The flashing wait may be sped up. The failure wait may not.
- Keep port names visible. Viewers compare theirs to yours.
- Caption every status string as `[status: …]`.
