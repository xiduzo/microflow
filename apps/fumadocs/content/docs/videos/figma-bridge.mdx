## Set up before you record

- A Figma file with one frame and one rectangle. Do not create the variable in advance.
- The Hardware Bridge plugin **not yet installed**. Installing it is part of the video.
- A broker configured in Studio. Write the identifier on a card you can read from.
- Both screens captured at the same resolution.

## Script

### 0:00 — What you are about to build

**Screen:** Split screen. Left: a hand covers the light sensor. Right: a rectangle in a Figma prototype darkens with it. Then reverse: a click in the prototype lights the LED on the desk.

**Narration:**
> "A sensor on the desk, changing a value in Figma. And a button in Figma, turning on a light on the desk. Both directions, no code."

### 0:35 — The middleman

**Screen:** A static diagram: Studio, broker, plugin, arrows both ways.

**Narration:**
> "Studio and Figma never talk directly. A Figma plugin cannot see your USB ports. Both ends connect to a message broker instead, and pass notes through it. So the whole setup comes down to one thing: both ends must agree on the address."

### 1:05 — Install the plugin

**Screen:** Figma. Install the Microflow Hardware Bridge from the community page. Run it from **Plugins**. The panel opens.

**Narration:**
> "In Figma, install the Microflow Hardware Bridge and run it. Everything on the Figma side happens in this panel. Leave it open. Closing a Figma plugin stops it, and the bridge stops with it."

**On-screen text:** `Plugins → Microflow Hardware Bridge`

### 1:45 — Match the identifiers

**Screen:** Side by side: the plugin's settings and Studio's MQTT configuration. Type the same broker URL into both, then the same identifier, on camera.

**Narration:**
> "Both ends need the same broker and the same identifier. The identifier separates your project from everyone else's on that broker. Type it carefully. It is case sensitive, and a mismatch looks exactly like a broken sensor."

**On-screen text:** `Same broker URL · same identifier · both ends`

### 2:30 — Sensor to Figma

**Screen:** In Figma, create a number variable named `light_level` in the MHB collection. In Studio: add an **LDR** node on A0, add a **Figma** node, select the broker, enter the identifier, and pick `light_level` from the **Variable** list. Connect LDR `value` to Figma `set`. Cover and uncover the sensor with both screens visible.

**Narration:**
> "In Figma, make a number variable called light-underscore-level. In Studio, add the light sensor and a Figma node. The Figma node reads the variable list from the plugin, so if your variable is in that dropdown, the connection is healthy. Pick it, connect the sensor, and cover the sensor. The number in Figma moves."

### 3:40 — Failure: mismatched identifier

**Screen:** In the plugin, change one character of the identifier. The status still reports a healthy connection. Cover the sensor: nothing changes. Hold for six seconds. Fix the character. It works again.

**Narration:**
> "Now the failure you will actually hit. I am changing one character of the identifier. The status is still green. No error anywhere. Cover the sensor and nothing happens, because Studio posts to one address and Figma listens at another. When the bridge says connected and nothing arrives, this is why."

**On-screen text:** `[connected · identifier mismatch · no error shown]`

### 4:25 — Figma to hardware

**Screen:** In Figma, create a boolean variable named `lamp_on` and a prototype button that toggles it. In Studio, add a second Figma node bound to `lamp_on`, and connect its `change` output to an LED node. Run the prototype and click the button. Cut to the LED.

**Narration:**
> "The other direction works the same way. A boolean variable, a prototype button that toggles it, and a second Figma node bound to that variable, driving the LED. Run the prototype. The light on the desk is now part of it."

### 5:25 — What to check when it stops

**Screen:** A checklist card, with a cut to each item in the UI.

**Narration:**
> "Three things, in this order. Is the plugin panel still open. Do the identifiers still match. Is the node still bound to the right variable. Almost every bridge problem is one of those three, and none of them are the hardware."

**On-screen text:**
```
1. Plugin panel open?
2. Identifiers identical?
3. Right variable selected?
```

## Deliberate failure

The one-character identifier mismatch at 3:40, shown with a healthy status. Do not trim it.

## Post-production notes

- Zoom the Figma UI rather than the recording if the variables panel is too small at 1080p.
- Never show a broker password, even briefly.
- Caption variable names exactly, including underscores.
