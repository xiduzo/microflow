## Set up before you record

- Deliberately leave the LDR wiring slightly long and untidy — you want real noise, not clean readings.
- A Monitor node in graph mode is on the canvas from the start; the graph is the star of this video.
- Note the room's actual dark and light readings before recording so the threshold number in the script matches what viewers will see.

## Script

### 0:00 — The problem, on a graph

**Screen:** Canvas with LDR → Monitor (graph). Zoom so the graph fills half the frame. Hold still — the trace visibly jitters even with nothing moving.

**Narration:**
> "Nothing in the room is changing, and the reading will not sit still. Every analog sensor does this. It is not a broken sensor and it is not a broken board — it is the last digit or two of a measurement that was never that precise to begin with. The trouble starts when you make a decision from it."

### 0:40 — Add Smooth

**Screen:** `Cmd/Ctrl + K`, add **Smooth**, drop it between the LDR and the Monitor. Rewire: LDR `value` → Smooth `value`, Smooth `value` → Monitor `value`. Set **Type** to `moving average` and **Window size** to `25`.

**Narration:**
> "Put a Smooth node in the middle. Set it to moving average with a window of twenty-five, and it reports the average of the last twenty-five readings instead of the newest one. Watch the graph settle."

**On-screen:** Hold on the graph for five seconds before and after so the difference is unmistakable.

### 1:40 — Smooth versus moving average

**Screen:** Change **Window size** from 25 to 100, then to 5, pausing on each. Then switch **Type** to `smooth` and set **Attenuation** to `0.995`, then `0.9`.

**Narration:**
> "Two ways to do this. Moving average is the blunt one: bigger window, calmer line, slower to react. A window of a hundred is glassy but it lags — cover the sensor and the graph takes a moment to notice. A window of five barely helps.
>
> The other mode, plain smooth, uses an attenuation between zero and one. Closer to one means heavier smoothing. It reacts more gracefully than a big window, but it never quite arrives at the value. Start with a moving average of twenty-five and only reach for the other one if the lag bothers you."

**On-screen text:** `window 25 · window 100 (laggy) · window 5 (still noisy)`

### 2:20 — Add Compare

**Screen:** Add a **Compare** node after Smooth. Set **Validator** to `number` and **Sub-validator** to `less than`, with the value at your measured dark threshold — say `300`. Wire Compare's `true` output into the LED's `true` input, and `false` into `false`.

**Narration:**
> "Now the decision. Compare takes a value and answers a yes-or-no question about it. Set it to *number*, *less than*, three hundred — because in this room, below three hundred means someone has covered the sensor. True and false out of Compare go straight into the LED's true and false."

**Screen:** Cover the sensor with a hand. The LED lights. Uncover. It goes out.

### 3:10 — Deliberate failure: chatter at the boundary

**Screen:** Temporarily set the Smooth window back to `1` (or bypass Smooth entirely by rewiring LDR → Compare). Hold a hand at exactly the boundary distance so the reading hovers around 300. Cut to hardware: the LED flickers rapidly. Hold for six seconds.

**Narration:**
> "Here is what happens without the smoothing. Hold the light right at the boundary and the reading crosses three hundred back and forth, dozens of times a second — so the LED does too. If that were a relay switching a lamp, you would hear it buzzing. This is the failure that sends people looking for a hardware fault, and it is not one."

**On-screen text:** `[reading oscillating 297–304]`

### 3:50 — Fix it

**Screen:** Restore the Smooth node with window `25`. Repeat the same hover — the LED now holds steady. Then add a **Delay** node between Compare and the LED and show it holding the signal.

**Narration:**
> "Smoothing first — the average does not cross the line nearly as often as the raw reading does. If it still chatters, a Delay node after the decision makes the flow wait before it acts, so a momentary blip never reaches the light. Smooth the input, then slow down the output. In that order."

### 4:30 — Recap

**Screen:** Zoom to fit the whole flow: LDR → Smooth → Compare → LED, with the Monitor hanging off the Smooth node.

**Narration:**
> "Four nodes and one shape you will use constantly. Sense the world. Shape the reading into something trustworthy. Decide something from it. Express the result. And keep a Monitor hanging off the middle of it while you build, because it is the only way to see which of those four is lying to you."

## Deliberate failure

The chattering boundary at 3:10 — recorded live, not staged in the edit.

## Post-production notes

- The graph is the subject: never let it drop below a third of the frame.
- Do not speed up any graph footage. Timing is the whole point of this video.
- Record the room's real threshold value on the day and update the spoken number to match. Do not say 300 if the sensor reads 640.
