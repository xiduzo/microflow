# Microflow Technical Guidelines

> Generated by `steer-tech`. Refine as the codebase evolves — do not regenerate from scratch.

Last updated: 2026-11-19

## Stack

**Monorepo:** Turborepo + Bun workspaces (`apps/*`, `packages/*`). Package manager pinned to `bun@1.3.5`. Shared deps declared in the workspace `catalog`.

**Microflow Studio (web + desktop):** `apps/web`
- React 19 + TanStack Router / Query / Form
- Vite 6
- Ships twice from one codebase: the web app at microflow.tech (Web Serial + the WebAssembly runtime) and the Tauri 2 desktop app (`apps/web/src-tauri`)
- `@xyflow/react` (ReactFlow) for the flow canvas
- Yjs + `y-protocols` for collaborative doc state
- Tailwind 4 + base-ui / shadcn / leva / Monaco

**Rust flow engine (`crates/microflow-core`):** Rust 1.77.2, edition 2021
- The sans-IO flow runtime, the Firmata codec, board bring-up, the flasher protocols and Arduino sketch generation
- `boa_engine` (in-flow JS, `js` feature), `thiserror`; dev: `criterion`
- Compiled to WebAssembly for the browser by thin shims: `crates/microflow-runtime-wasm`, `microflow-firmata-wasm`, `microflow-codegen-wasm`

**Desktop host (`apps/web/src-tauri`):** Rust 1.77.2, edition 2021
- `tauri 2.9`, `tokio` (sync/rt/macros/time/net), `serialport`
- `mqtt-endpoint-tokio` (TLS + WS), `reqwest` (rustls), `dashmap`, `thiserror`
- Dev: `proptest`

**Server (`apps/server`):** Hono + tRPC + better-auth, Bun runtime, compiled with `tsdown` / `bun build --compile`.

**Packages (`packages/*`):** `@microflow/api` (tRPC routers), `@microflow/auth` (better-auth + Polar), `@microflow/collab` (Yjs + y-protocols), `@microflow/db` (Drizzle + Postgres; `@microflow/db/testing` is the in-process Postgres for tests), `@microflow/env` (t3-oss env), `@microflow/config` (shared tsconfig).

**Design-tool plugins:** `apps/figma-plugin` (`create-figma-plugin` + Preact, React imports aliased to `preact/compat`), `apps/penpot-plugin` (Vite + React). Both build on `@microflow/design-bridge` (`packages/design-bridge`): the shared MQTT protocol, the plugin-side bridge engine, the plugin bridge session (settings, the broker connection over mqtt.js, presence, polling), UI stores and sandbox routing ([ADR-0040](../adr/0040-plugin-bridge-session.md)). Studio's web code uses the same package; `crates/microflow-core/src/design_bridge.rs` is the Rust mirror, and both are checked against `packages/design-bridge/fixtures/protocol.json` ([ADR-0028](../adr/0028-design-tool-bridge-protocol.md)).

**Docs:** `apps/fumadocs` (Next 16 + fumadocs-ui).

## Architecture

- **Component Catalog drives everything.** `apps/web/node-components.json` is the single source of truth. Codegen produces `apps/web/src/nodes/component-types.generated.ts`, `catalog.generated.ts` (React-free metadata) and `node-types.generated.ts` (UI), plus `apps/web/node-defaults.generated.json` (what the editor writes into each node's `data`, for the Catalog Parity Guard). The Rust side is hand-registered in `ComponentRegistry::register_all` (`crates/microflow-core/src/runtime/registry.rs`); `apps/web/src-tauri/build.rs` generates nothing.
- **Flow Runtime is sans-IO and single-owner.** `FlowRuntime` (`crates/microflow-core/src/runtime/`) builds a `ComponentRegistry` of factory closures; `update_flow` reads each node's `data` through `config::resolve`, instantiates `Box<dyn Component>` per node and rebuilds `Wiring`. Every entry point returns one `Effects` record that the Runtime Host applies ([ADR-0006](../adr/0006-rehost-runtime-on-core.md), [ADR-0033](../adr/0033-one-node-config-resolution.md)).
- **Hardware IO has one owner per host.** The Board Link owns the serial port: the runtime actor's Board Session on desktop, `SerialBoardLink` in the browser. Components encode Firmata through the `BoardWriter` into the turn's outbound bytes; they never touch serial directly.
- **Event routing is typed per kind** (per ADR-0001): Ports (flow edges into `dispatch`), Internal Events (self-routed `_`-prefixed handles), Hardware Callbacks (board-reader-driven, reserved names like `_pin_change` / `_i2c_reply`).
- **Collaboration via Yjs.** Doc state syncs through `@microflow/collab` / apps/server. CRDT semantics; last-writer-wins. The room is the only path between two clients, tabs of one browser included (`SyncProvider` passes `disableBc: true` to y-websocket). Stored edges are read through `decodeEdge` (`packages/collab/src/schema.ts`), the same decoder a Flow File import uses.
- **TS path alias `@/` → `apps/web/src/`** (`tsconfig.base.json`).

## Key Constraints

- The Component Catalog is the single source of truth. Never hand-edit a `*.generated.ts` or `*.generated.json` file; edit `node-components.json`, the node's schema or the Rust node, and run `bun run catalog:sync` in `apps/web`.
- The Board Link has exclusive ownership of the serial port. All hardware work goes through the `BoardWriter` into `Effects.outbound_bytes`.
- Never block, sleep or do I/O in a node. `BoardWriter` methods encode and return; a timer is a `Wakeup` the host arms.
- Never read the OS clock in core. Time is the engine clock the host hands in (`ctx.now_ms()`); on wasm the OS clock panics. `clippy.toml` in `crates/microflow-core` and `crates/microflow-runtime-wasm` bans `std::time::Instant` and `SystemTime`.
- Domain language from `CONTEXT.md` is enforced. Use Component / Port / Wiring / Hardware Callback / BoardWriter — not generic substitutes ("handler", "event").
- Always use `bun` (not `npm`, `pnpm`, or `yarn`). `packageManager` is pinned.
- Clippy pedantic must pass: `cargo clippy --workspace --all-targets -- -D warnings -W clippy::pedantic`. oxlint must pass, including the `microflow/*` architecture rules for `apps/web/src` (needs Node 22.18+).
- Rust runtime errors flow through `RuntimeError` (`thiserror`). No `anyhow`, no `panic!` in component code.
- TS imports use the `@/` alias for `apps/web/src/`. No deep relative paths (`../../...`).

## Commands

```bash
# Install
bun install

# Dev — all apps
bun run dev

# Dev — single app
bun run dev:web
bun run dev:server

# Desktop dev (Tauri)
cd apps/web && bun run desktop:dev

# Desktop build
cd apps/web && bun run desktop:build

# Component-catalog codegen (run when node-components.json or a node schema changes)
cd apps/web && bun run codegen

# Rust ports/emits or a node config changed: bless, codegen, then the Catalog Parity Guard
cd apps/web && bun run catalog:sync

# Type check
bun run check-types

# Lint + format (oxlint + oxfmt)
bun run check

# Rust clippy (matches CI gate; from the repo root)
cargo clippy --workspace --all-targets -- -D warnings -W clippy::pedantic

# Rust tests (matches CI gate; from the repo root)
cargo test --workspace --lib --tests

# Rust bench (engine hot paths)
cargo bench -p microflow-core --features runtime --bench runtime

# Database
bun run db:start     # docker compose up -d postgres
bun run db:push      # drizzle-kit push
bun run db:studio
bun run db:migrate
```

## Code Conventions

- **Naming:** PascalCase for React components and Rust types; camelCase for TS functions; snake_case for Rust modules/functions; kebab-case for TS file names where existing files do so (e.g. `host-adapter.ts`).
- **TS file structure:** `apps/web/src` is split into domain verticals (`nodes/`, `editor/`, `session/`, `runtime/`, `board/`, `cloud/`, `ai/`, `sketch/`, `circuit/`, `flows/`, `community/`, `account/`, `devtools/`, `shell/`), an infrastructure layer (`platform/`, `ui/`, `lib/`) and `routes/`, which composes them ([ADR-0027](../adr/0027-web-app-domain-verticals.md); one line per vertical in [`ARCHITECTURE.md`](../../ARCHITECTURE.md#where-does-new-code-go)). Each vertical keeps its own components, hooks and stores. Another vertical imports only the public files listed for it in `apps/web/scripts/architecture/verticals.ts`; `bun test src/architecture.test.ts` (in `apps/web`) enforces it. Flow nodes live in `src/nodes/<node>/` (kebab-case) with a React-free `<node>.handles.ts` (its Handle Rule) and a `<node>.adapter.ts` sibling when one exists.
- **Rust file structure:** `crates/microflow-core/src/` — shared engine in `runtime/` (`component.rs`, `router.rs`, `registry.rs`, `context.rs`, `wiring.rs`, `board.rs`, …, behind the `runtime` feature) and Arduino codegen in `codegen/` (`emit.rs`, `wire.rs`, `validate.rs`, `parity.rs`, …, ungated). Each Node's own code lives in one directory, `nodes/<node>/` — `config.rs` (ungated, read by both other layers through `config::resolve`, [ADR-0033](../adr/0033-one-node-config-resolution.md)), `runtime.rs` (behind `runtime`, or `cloud` / `js`), `codegen.rs` (ungated) — only the layers it has ([ADR-0026](../adr/0026-node-code-colocated-per-node.md)). Adding a Node: create `nodes/<node>/`, add `pub(crate) mod <node>;` to `nodes/mod.rs`, then one line each in `runtime/registry.rs::register_all`, `codegen::emit_node` / `output_expression`, and `codegen/parity.rs::classify` (plus the `codegen/validate.rs` pin tables for a Node that owns pins, and `exports_without_reading_settings` in `codegen/parity.rs` for a Node with no emitter). `impls[].category` is a catalog label, not a module path. `nodes` is `pub(crate)`, and the `nodes/boundaries.rs` unit test fails when a Node names another Node, a file outside the central dispatch tables names a Node, `nodes/mod.rs` and the Node directories disagree, or a Node's emitter resolves another config than its runtime is built from.
- **Rust tests:** unit tests beside the code; desktop integration tests in `apps/web/src-tauri/tests/*.rs` with shared helpers under `tests/support/`. Use the Sim board (`SimBoard`, `SimRig`) instead of touching real hardware ([ADR-0030](../adr/0030-hardware-tested-at-the-byte-seam.md)).
- **TS imports:** absolute via `@/`. Workspace packages via `@microflow/<name>`.
- **Env:** validated by `@microflow/env` (`./server` vs `./web` exports via t3-oss).

## Architecture Decision Records

- [ADR-0001 — Component trait separates Port, Internal Event, and Hardware Callback flows](../adr/0001-component-trait-flow-separation.md) — accepted 2026-05-16.

Additional decisions captured here pending ADRs:

- **T-stack monorepo (Turborepo + Bun workspaces).** All apps + packages share one repo; cross-package deps via `workspace:*`; shared versions via Bun `catalog`.
- **Tauri 2, not Electron.** Rust runtime is the primary reason — co-locating the flow executor with the desktop shell beats an IPC bridge to a separate process.
- **Yjs (CRDT) for collaboration.** Not OT. Last-writer-wins is acceptable for flow docs; chosen so collaboration also works offline.
- **Drizzle + Postgres for server persistence.** Yjs doc snapshots stored via `@microflow/collab`; relational data (auth, billing) on the same Postgres.

## Known Pain Points

- **Firmata wire reliability + reconnects.** Serial drops, board resets, and slow handshakes are real. Broker sessions and reconnects are covered by `tests/mqtt_pool.rs` and `tests/mqtt_reconnect.rs`, message routing by `tests/mqtt_routing.rs`; the board side by the Sim board's fault injection. Treat this as a hot spot: when changing a Board Link or the runtime's session handling, add a Sim board test first, and run the hardware smoke suite before merge.
